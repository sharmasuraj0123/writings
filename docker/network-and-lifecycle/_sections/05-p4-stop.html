{{S}}Signals, stop and restart

docker stop is a signal, a wait and a SIGKILL. On the wire it is one request. Against the mock daemon, docker stop -t 3 -s SIGINT web sent POST /v1.56/containers/web/stop?signal=SIGINT&t=3, and a plain docker stop web sent no query at all, so the container's own StopTimeout applies measured here. docker kill -s HUP became kill?signal=HUP. The daemon side is in moby/daemon/stop.go:85-89, 115-118 from the code: 

	// 1. Send a stop signal
	err := daemon.killPossiblyDeadProcess(ctx, ctr, stopSignal)
	if err != nil {
		wait = 2 * time.Second
	}
…
	// Stop either failed or container didn't exit, so fallback to kill.
	if err := daemon.kill(ctx, ctr); err != nil {

The signal is the container's StopSignal, else SIGTERM. The wait is the request's t, else the container's StopTimeout, else 10 seconds on Linux. A negative timeout waits forever. The stop runs under context.WithoutCancel, so pressing Ctrl-C on docker stop does not abort it, and stopping a stopped container returns 304 from the code.

Only PID 1 hears it

The signal travels dockerd → containerd Task.Kill → shim → a fresh runc kill <id> <sig> → the container's init process. Nothing else in the container is signalled; only SIGKILL with a shared PID namespace is fanned out to the whole cgroup (runc/libcontainer/container_linux.go:396-426). Then the kernel applies its rule for a namespace's init process: a signal for which init has no handler is dropped, even when root sends it. Only SIGKILL and SIGSTOP from an ancestor namespace are forced (pid_namespaces(7)). A sh or a naive binary as PID 1 never sees the SIGTERM. docker stop therefore always waits the full timeout and ends in SIGKILL. The exit code is 137 because the shim's reaper encodes a signal death as 128 plus the signal number (containerd/pkg/sys/reaper/reaper_unix.go:280-289) from the code. Figure {{fig-stop-timeline}} draws the clock. --init puts tini v0.19.0 in front as PID 1; it has handlers and forwards the signal to the real program, which then dies of the default action (Part 1 §03 shows the rewrite).

The restart manager, and D77

After an exit, the restart manager decides. Its backoff is 100 ms, doubling on each restart, capped at one minute, and reset whenever the last run lasted 10 seconds or more (moby/daemon/internal/restartmanager/restartmanager.go:11-15, 65-78). always restarts, unless-stopped restarts unless hasBeenManuallyStopped, on-failure[:N] restarts on a non-zero exit while the count is below N, and no returns before taking any lock. A manual stop also cancels the manager outright, so after docker stop no policy restarts at exit. The policies diverge only at daemon startup, where a stopped always container comes back and an unless-stopped one does not from the code.

The flag that makes a stop "manual" is set in moby/daemon/kill.go:80-103, and its placement is finding D77 from the code: 

var unpause bool
if container.Config.StopSignal != "" && stopSignal != syscall.SIGKILL {
	containerStopSignal, err := signal.ParseSignal(container.Config.StopSignal)
	if err != nil {
		return err
	}
	if containerStopSignal == stopSignal {
		container.ExitOnNext()
		unpause = container.State.Paused
	}
} else {
	container.ExitOnNext()
	unpause = container.State.Paused
}

if !daemon.IsShuttingDown() {
	container.HasBeenManuallyStopped = true
	if err := container.CheckpointTo(ctx, daemon.containersReplica); err != nil {
	…
}

ExitOnNext cancels the manager. Without a StopSignal in the config, the else branch runs for any signal, so docker kill -s HUP cancels always and on-failure too. And HasBeenManuallyStopped = true sits outside the if/else, so every docker kill -s marks the container as manually stopped, even with a STOPSIGNAL. It is checkpointed to disk, so it also survives a daemon restart. Send SIGHUP to reload nginx, and the next crash of an unless-stopped container is never restarted. PR #26464 (v1.13.0, 2016) fixed only the ExitOnNext half. Issues #41302 and #47792 are open, and fix PR #53415 has been open and unmerged since 2026-08-19. kill.go is byte-identical on master. The workaround is to signal the process directly, with docker exec c kill -HUP 1. Figure {{fig-restart-policy}} lays out every case.
