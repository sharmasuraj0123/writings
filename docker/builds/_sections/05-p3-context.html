{{S}}The context is pulled, not pushed

A client that sends a build might be expected to upload its directory. BuildKit reverses the direction: the client is the gRPC server. buildx registers a file-sync provider in its session, and BuildKit calls FileSync.DiffCopy (or the older TarStream) back into it, both bidirectional streams of fsutil.types.Packet (buildkit/session/filesync/filesync.proto:10-13). What to send travels as gRPC metadata on that call, under four keys (session/filesync/filesync.go:25-30) from the code: 

const (
	keyIncludePatterns    = "include-patterns"
	keyExcludePatterns    = "exclude-patterns"
	keyFollowPaths        = "followpaths"
	keyDirName            = "dir-name"
	keyExporterMetaPrefix = "exporter-md-"

The client applies those filters itself before anything is sent, by wrapping the directory in fsutil.NewFilterFS (filesync.go:110-145). An excluded file is never read and never leaves the client from the code. That is the practical meaning of .dockerignore now: it trims what is sent, not only what COPY sees.

Three transfers per build

A Dockerfile build makes three separate local transfers, and they are the first three lines of --progress=plain output (frontend/dockerui/config.go:348-363, 522-585). [internal] load build definition reads the Dockerfile from the dockerfile local, with FollowPaths limited to the Dockerfile, <Dockerfile>.dockerignore and dockerfile. load .dockerignore reads .dockerignore from the context local, used only if no per-Dockerfile ignore file was found. load build context is the filtered main context from the code. The last one is narrowed twice. The exclude patterns come from .dockerignore. The FollowPaths come from the Dockerfile: each COPY/ADD source and each RUN --mount bind source is added to ctxPaths, which becomes llb.FollowPaths on the context source (dockerfile2llb/convert.go:1145-1150, 1850-1875; convert_runmount.go:141-146). For Figure {{fig-dockerfile-llb-dag}} that is go.mod and main.go and nothing else. COPY . . names the path / and switches the narrowing off.

The wire: STAT, REQ, DATA, FIN

DiffCopy speaks fsutil's packet protocol, five types in one enum (buildkit/vendor/github.com/tonistiigi/fsutil/types/wire.proto:10-23; fsutil v0.0.0-20260819142231-83cac42c1c52 as vendored): 

  enum PacketType {
    PACKET_STAT = 0;
    PACKET_REQ = 1;
    PACKET_DATA = 2;
    PACKET_FIN = 3;
    PACKET_ERR = 4;
  }

The sender streams one STAT for every file that survived the filters and ends the list with an empty STAT (fsutil/send.go:182). The receiver compares each record with what it already holds and answers REQ <id> only for files that differ (receive.go:425). The sender returns DATA chunks for each requested id, with an empty DATA to close a file (send.go:146). The receiver sends FIN and the sender answers it (receive.go:224; send.go:101-106) from the code. Figure {{fig-context-transfer}} draws one exchange.

The incremental part lives on the daemon side. BuildKit keeps a retained mutable snapshot per name:sharedKeyHint:<client shared key> and syncs into it again on the next build, so a second build sends only the files that changed, and a cacheUpdater updates the content-hash records of §04 as files land (source/local/source.go:204-280) from the code. The content key a COPY needs is therefore mostly computed before the solver asks for it reconstruction.

The same inversion covers everything else a build takes from the client. A secret's bytes are fetched over the session with secrets.GetSecret when a RUN mounts it, and an SSH mount is a socket that proxies back to the client's agent over the same session (solver/llbsolver/mounts/secretmount_unix.go:16-75; mounts/mount.go:200-239) from the code. Nothing is uploaded in advance; dockerd asks when a step needs it.

One boundary surprises people. .dockerignore patterns are applied to context COPYs as an ignore matcher, but not to COPY --from=<stage>, whose source is another stage's filesystem (dockerfile2llb/convert.go:1120-1132). That is register D60, class D: expected from the code, often assumed otherwise from the code.
