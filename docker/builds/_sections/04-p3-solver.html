Edges, states and a scheduler

Every op implements CacheMap (how to key it), Exec (run it) and Acquire. CacheMap.Digest is the op's own checksum; each Deps[i] may add a Selector and a ComputeDigestFunc that keys input i by its content (buildkit/solver/types.go:169-249). Both calls run at most once per vertex, behind flightcontrol groups (solver/jobs.go:1164-1166, 1243-1250). One scheduler goroutine pops edges off a queue and calls edge.unpark; the real work runs in async functions connected to edges by "pipes" (solver/scheduler.go:61-96). Each edge moves through four states, declared in solver/edge.go:14-21 as edgeStatusInitial, edgeStatusCacheFast, edgeStatusCacheSlow and edgeStatusComplete. The solver raises an input's desired state only as far as the current edge needs from the code. So if one input already gives a definition-based match, the others are never content-hashed, and an image input is never pulled (docs/dev/solver.md:25-29). Layers are lazy anyway: the puller records a handle per layer at key time and fetches bytes only when a later step needs the snapshot (source/containerimage/pull.go:156-171). Figure {{fig-cache-keys}} shows the two tiers.

The fast key: a scrubbed definition

A root key is sha256("<cacheMapDigest>@<output>") (solver/cachemanager.go:451-457). A key with dependencies is not a hash chain. It is a node in a link graph, found by following CacheInfoLink{Input, Output, Digest, Selector} edges out of each dependency's keys, and given a random ID when no link exists yet. The links persist in cache.db's four bbolt buckets, _result, _links, _byresult and _backlinks from the code. For an ExecOp, CacheMap hashes JSON {Type: "buildkit.exec.v0", Exec: op, OS, Arch, …} of a cleaned copy of the op (solver/llbsolver/ops/exec.go:114-132): 

func (e *ExecOp) CacheMap(ctx context.Context, jobCtx solver.JobContext, index int) (*solver.CacheMap, bool, error) {
	op := cloneExecOp(e.op)

	for i := range op.Meta.ExtraHosts {
		h := op.Meta.ExtraHosts[i]
		h.IP = ""
		op.Meta.ExtraHosts[i] = h
	}

	for i := range op.Mounts {
		m := op.Mounts[i]
		m.Selector = ""

		if checkShouldClearCacheOpts(m) {
			m.CacheOpt.ID = ""
			m.CacheOpt.Sharing = 0
		}
	}
	op.Meta.ProxyEnv = nil

Proxy settings, --add-host IPs, mount selectors and a cache mount's custom id or non-default sharing all drop out (register D53, D54, both class D, intended). Separately, getMountDeps skips secret, SSH and tmpfs mounts, so a rotated secret value never invalidates a cached RUN (exec.go:297-303; D52, class D). A RUN mount gets a content key only when that is safe, with no output or read-only (exec.go:315-337) from the code. All three are unchanged on BuildKit's master.

The slow key: a tarsum without mtime

A FileOp copy's own digest keeps only the basename of each source. The full paths, with wildcard, include and exclude settings, become that input's Selector, and a ComputeDigestFunc content-hashes exactly those paths (ops/file.go:110-119, 160-180). A file's record starts as a tar header built from its stat, with the file bytes after it. The header is serialised in "V1 tarsum" order, which is the legacy v0 field list minus one field (buildkit/cache/contenthash/tarsum.go:60-67): 

// Copy all headers from v0 excluding the 'mtime' header (the 5th element).
v0headers := v0TarHeaderSelect(h)
orderedHeaders = append(orderedHeaders, v0headers[0:5]...)
orderedHeaders = append(orderedHeaders, v0headers[6:]...)

A directory hashes each child's key and digest in radix-tree order, several selectors are hashed in parallel, and the input's key is sha256 of their NUL-joined digests. When it is ready, edge.go:708-721 builds NewCacheKey(dgst, "", -1) and calls Cache().Query to link the definition keys to it from the code. That link is the payoff. The local context's own key includes the session ID, so [internal] load build context never matches across builds (source/local/source.go:129-162); a COPY hits only because identical bytes produce an identical content key. Mode, owner and xattrs count; mtime does not (D61, class D). Image sources key on {Digest: <manifest digest>, OS, Arch, …}. Since v0.34.0, commit 5cf302ff6, the config's DiffIDs are no longer an alternate key, because they are unverified at lookup and could poison the cache (source/containerimage/pull.go:62-84, 175-183; D62, class E).
