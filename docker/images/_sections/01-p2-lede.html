{{S}}An image is a tree of hashes

A container is an ordinary Linux process, and Docker is five programs that agree on names made of sha256 hashes. This part is about those names. An image is a tree of JSON documents and tarballs. Every node is named by the sha256 of its exact bytes, so a name you trust fixes everything below it. The registry is trusted at one point only: the response header that turns a tag into a digest. Everything after that is checked on arrival.

The unit is the descriptor: a mediaType, a digest and a size, with optional urls, annotations and data (image-spec/descriptor.md:27-60) from the code. A digest is <alg>:<encoded> over the exact bytes; for sha256 that is 64 lowercase hex characters. The spec asks a consumer to check size before hashing, which bounds the read. Three document types use descriptors. An index points at one manifest per platform. A manifest points at one config and an ordered list of layers, base first. The config is the runtime defaults plus the list of uncompressed layer hashes. Its sha256 is the OCI ImageID (image-spec/config.md:85-89). Both index and manifest carry schemaVersion: 2, which the spec says exists only for Docker compatibility and will never change. Each index entry carries a platform. containerd's matcher normalises the arm64 variant v8 to the empty string, so linux/arm64 and linux/arm64/v8 select the same entry (moby/vendor/github.com/containerd/platforms/database.go:87-94) from the code.

The attestations point at their image through the annotation vnd.docker.reference.digest, not through subject. Hub does implement the OCI referrers endpoint. Asked for the amd64 digest, it returns 200 with an empty index measured here. A tool that finds SBOMs only through referrers finds none (register D29). That is the legacy layout: since v0.32, BuildKit's image exporter also writes each attestation manifest as an OCI artifact with subject by default, so images built that way can be found through referrers on registries that index it (exporter/containerimage/writer.go:613-678) from the code. Older tags show the format before BuildKit: alpine:3.10 and 3.15 are still served as Docker manifest lists, and their configs carry the Docker-only keys container, container_config and docker_version. The two families map one to one: the manifest list is the index, and the Docker gzip layer type is "interchangeable and fully compatible" with OCI's (image-spec/media-types.md:41-64).
