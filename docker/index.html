Docker, taken apart

A container is an ordinary Linux process. Docker is a relay of five separate programs (the docker CLI, dockerd, containerd, a per-container shim and a short-lived runc) that agree on names made of sha256 hashes and on a JSON spec, ask the kernel to narrow one process's view of the machine, and then mostly get out of the way. Most surprises live at a seam between two of them. This collection reads every seam from the source, measures what can be measured, and keeps a register of where the code, the docs and users' expectations disagree.

Four parts, read in order or alone. Every claim cites a file and line at Docker Engine 29.9.2 (moby@0367cbeb), docker/cli 29.9.2, containerd v2.4.2, runc v1.5.2, BuildKit v0.34.1 or the OCI specs, or a measurement. No container could run on the research machine, so "measured" means registry traffic, image bytes, digests and this host's own cgroup files; container behaviour is read from the code and labelled so. Each part is one self-contained HTML file.

The collection

  • Part 1·23 October 2026·34 min read

    From docker run to a process

    A container is an ordinary Linux process, and docker run is five programs passing it along. This first part of a four-part teardown follows one docker run -it alpine sh through Docker Engine 29.9.2: five API calls on three connections, a create that only writes JSON, a start that rebuilds the whole OCI spec, a shim that daemonises itself and adopts the container, runc building namespaces in C before Go boots, a FIFO that holds the process while dockerd plugs in the network, and the exit status climbing back through three protocols.

  • Part 2·23 October 2026·32 min read

    Images, layers and the registry

    An image is a Merkle tree of JSON documents and tarballs, each named by the sha256 of its exact bytes. This second part of a four-part Docker teardown pulls alpine:latest from Docker Hub request by request, takes its 9,218-byte index, its config and its one layer apart byte by byte, derives the three hashes of the same layer (digest, DiffID, ChainID), follows the layer into containerd's content store and overlay snapshots, compares Docker 29's two image stores, and pushes into a local registry to watch its storage, its Accept rules and its garbage collector.

  • Part 3·23 October 2026·29 min read

    How BuildKit builds

    BuildKit never executes a Dockerfile. This third part of a four-part Docker teardown follows docker build from the CLI's argv rewrite into buildx and over gRPC into the BuildKit inside dockerd, compiles a Dockerfile into LLB, re-derives three vertex digests of alpine:latest's real build byte for byte from its published provenance, takes the solver's two cache keys apart to show why a comment or a touch keeps the cache and a chmod busts it, watches the daemon pull the build context from the client, and ends at the exporters, the cache formats and the attestations a build writes.

  • Part 4·23 October 2026·43 min read

    Networks, I/O and the long run

    After runc start, Docker is byte pipelines and small state machines, and both lose or block more than users assume. This last part of a four-part teardown follows -p 8080:80 through netfilter and docker-proxy, finds the DNS server at 127.0.0.11 running inside dockerd, takes apart the 8-byte frame behind attach and logs, times docker stop to its SIGKILL, shows how docker kill -s HUP can switch off a restart policy, reads health, OOM, stats and events as thin readers over cgroup files and in-memory rings, tells thirteen years of moving work out of one binary, and ends with the register of all 100 findings.
