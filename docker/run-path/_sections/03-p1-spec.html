{{S}}Create is bookkeeping; start builds the world

POST /containers/create touches no runtime at all. It resolves the image locally, merges the config, allocates an ID and a name, creates the read-write layer, writes JSON to disk and emits a create event (moby/daemon/create.go:171-290). containerd is not called until start. A missing image gives the 404 that the CLI's pull-and-retry waits for from the code.

The ID is 32 random bytes in hex, 64 characters, drawn again if its 12-character short form is all digits, because the short ID becomes the default hostname (moby/daemon/internal/stringid/stringid.go:36-60). The program is fixed now from Entrypoint and Cmd; for alpine sh that is Path:"sh" with no args (moby/daemon/container.go:134-157). The record lands in /var/lib/docker/containers/<id>/, created mode 0710, as two files written atomically with mode 0600: config.v2.json and hostconfig.json. They are split on purpose. HostConfig carries json:"-" with the comment "do not serialize the host config in the json, otherwise we'll make the container unportable" (moby/daemon/container/container.go:105) from the code. Every later state change is checkpointed twice, to disk and into an in-memory go-memdb replica that answers docker ps without taking container locks (container/container.go:225-238).

One CLI flag writes more than JSON. After create, --use-api-socket copies a config.json holding the user's resolved registry credentials to /run/secrets/docker/config.json in the writable layer (cli/cli/command/container/create.go:244-310). The comment there admits it: "This can leave around the config if the container doesn't get deleted" (create.go:268-269; finding D8, class D) from the code.

Start, under one lock

containerStart runs under the container lock: mount the read-write layer, set up the network sandbox and mounts, createSpec, ReplaceContainer in containerd, NewTask (shim plus runc create), initializeCreatedTask (network into the new netns), tsk.Start (runc start), SetRunning, health monitor, checkpoint, start event (moby/daemon/start.go:82-271) from the code.

The OCI spec is not stored at create. It is regenerated on every start: oci.DefaultSpec() plus about seventeen SpecOpts in a fixed order, from cgroups through namespaces, capabilities, seccomp and mounts to the masked paths (moby/daemon/oci_linux.go:1024-1079) from the code. So a daemon upgrade changes the sandbox of an existing container the next time it starts reconstruction. Figure {{fig-spec-layers}} lists what that spec takes away, who applies each part, and what the same files read on this sandbox, which is itself a container.

Defaults worth knowing

Since docker-v29.5.0 the default namespace list includes a private time namespace (moby/daemon/pkg/oci/defaults.go:117-124; commit d5370d34d3, 7 April 2026), dropped on kernels older than 5.6 or with the daemon feature "time-namespaces": false. Tools that compare /proc/<pid>/ns/time, or run nsenter without -T, now see a new namespace (finding D17, class E) from the code. The 14 capabilities are CHOWN, DAC_OVERRIDE, FSETID, FOWNER, MKNOD, NET_RAW, SETGID, SETUID, SETFCAP, SETPCAP, NET_BIND_SERVICE, SYS_CHROOT, KILL and AUDIT_WRITE, in the bounding, permitted and effective sets only (moby/daemon/pkg/oci/caps/defaults.go:4-21). For a private network namespace dockerd also sets net.ipv4.ip_unprivileged_port_start to 0, so ports below 1024 bind without CAP_NET_BIND_SERVICE (oci_linux.go:753-775). Seccomp is inlined into the spec, and not applied at all for --privileged unless a profile is given (moby/daemon/seccomp_linux.go:19-58) from the code.

--init is a spec rewrite, and only for a private PID namespace, moby/daemon/oci_linux.go:731-745 from the code: 

if c.HostConfig.PidMode.IsPrivate() {
	if (c.HostConfig.Init != nil && *c.HostConfig.Init) ||
		(c.HostConfig.Init == nil && daemonCfg.Init) {
		s.Process.Args = append([]string{inContainerInitPath, "--", c.Path}, c.Args...)
		path, err := daemonCfg.LookupInitPath() // this will fall back to DefaultInitBinary and return an absolute path

			return err
		}
		s.Mounts = append(s.Mounts, specs.Mount{
			Destination: inContainerInitPath,
			Type:        "bind",
			Source:      path,
			Options:     []string{"bind", "ro"},
		})
	}

The binary bind-mounted read-only at /sbin/docker-init is tini: the installed /usr/libexec/docker/docker-init --version prints tini version 0.19.0 - git.de40ad0 measured here. Without it, sh is PID 1, which per pid_namespaces(7) gets only the signals it has handlers for reconstruction. The CLI sends "Init":true only when the flag is given, and null otherwise so the daemon's own default applies (cli/cli/command/container/opts.go:724-727) from the code.
