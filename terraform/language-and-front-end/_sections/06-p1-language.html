{{S}}The language surface: a dozen small schemas

"The Terraform language" is not a grammar. It is a set of schemas applied to HCL bodies, each with its own decoder in internal/configs. The top of a .tf or .tf.json file is one schema, configFileSchema, with fifteen block types and no attributes at all (internal/configs/parser_config.go:324-387) from the code: terraform, required_providers, provider, variable, locals, output, module, resource, data, ephemeral, action, moved, removed, import and check. One of those is a trap on purpose: a top-level required_providers is accepted by the schema only "so we can create a specialized error message hinting the user to nest it inside a "terraform" block". A bare x = 1 at the top of a file is "Unsupported argument".

terraform {} has its own schema: required_version, experiments and language, and the blocks backend, cloud, required_providers, state_store and provider_meta. state_store is rejected unless experiments are allowed, which means an experimental build (parser_config.go:117-178, 389-417). Resources: four meta-arguments and an escape hatch

resource, data and ephemeral share count, for_each, provider and depends_on. resource adds the blocks lifecycle, connection and provisioner, and all three accept a reserved locals block and a block named _ (internal/configs/resource.go:941-988) from the code. _ is the meta-argument escape. A provider whose resource has an argument called count or provider cannot have it set at the top of the block, because Terraform takes those names first; inside _ { … } the same names go to the provider, because the block's body is merged into the provider-config body with hcl.MergeBodies (resource.go:347-365). It arrived in v1.1.0 (commit 27ad9861ce, 14 May 2021) and has never been mentioned in a CHANGELOG.

lifecycle accepts create_before_destroy, prevent_destroy, ignore_changes, replace_triggered_by, destroy (v1.16.0, #38784) and the blocks precondition, postcondition and action_trigger (resource.go:990-1017). action_trigger and the top-level action block show how a schema can run ahead of its decoder: in v1.13.0 both were decoded only behind experiments, but the root schema already listed action, so a stable 1.13 binary accepts an action block and silently drops it. Actions shipped in v1.14.0 (#37553). If an action appears to do nothing, check the binary is at least 1.14.

The other blocks are tiny fixed schemas

provider takes alias, version and the provider's own configuration; count, depends_on, for_each and source are reserved, so Terraform, unlike OpenTofu, has no provider for_each (provider.go:262-284). module requires source and accepts version, count, for_each, depends_on, providers and ignore_nested_deprecations, and those names are therefore reserved as variable names: variable "source" is "Invalid variable name" (module_call.go:204-237) measured here. output takes description, value, depends_on, sensitive, ephemeral and, since v1.15, type and deprecated.

The refactoring and checking blocks are smaller still. moved is { from, to }; removed is { from } plus lifecycle { destroy }, connection and provisioner; import is to (required), id, identity, for_each and provider (moved.go:64-72; removed.go:137-154; import.go:117-133) from the code. check holds assert blocks and scoped data blocks; a check with no asserts, or an assert whose condition references nothing, is rejected, and checks cannot appear in override files. action "type" "name" takes count, for_each, provider and one config block (action.go:300-339). Part 3 follows what these blocks do once decoded.

Variables: nine arguments, and one that was never announced

variable accepts description, default, type, sensitive, ephemeral, nullable, deprecated, const and validation blocks. default is evaluated with a nil context, given its optional() defaults, then converted (named_values.go:63-247). Since v1.9 (#34955) a validation rule may reference other objects, but its condition must still mention var.<self> or it is "Invalid variable validation condition". An ephemeral variable passed into an ordinary argument is "Invalid use of ephemeral value", while the same value passed into a write-only argument validates measured here.

const is the switch that makes §08 work. It arrived in commit 4da132e639 on 11 February 2026, first tagged in v1.15.0, and no CHANGELOG from v1.5.0 to v1.17.0 names it; the v1.15.0 entry says only that module sources accept variables and locals. internal/configs/named_values.go:141-164 from the code: 

	if attr, exists := content.Attributes["const"]; exists {
		valDiags := gohcl.DecodeExpression(attr.Expr, nil, &v.Const)
		diags = append(diags, valDiags...)
		v.ConstSet = true
	}

	if v.Const {
		if v.Sensitive {
			diags = append(diags, &hcl.Diagnostic{
				Severity: hcl.DiagError,
				Summary:  "Const variable cannot be sensitive",
				Detail:   "A variable that is marked as \"const\" cannot also be marked as \"sensitive\".",
				Subject:  v.DeclRange.Ptr(),
			})
		}
		if v.Ephemeral {
			diags = append(diags, &hcl.Diagnostic{
				Severity: hcl.DiagError,
				Summary:  "Const variable cannot be ephemeral",
				Detail:   "A variable that is marked as \"const\" cannot also be marked as \"ephemeral\".",
				Subject:  v.DeclRange.Ptr(),
			})
		}
	}

Note the nil context again: const itself must be a literal. A const value can steer module addresses, so it may not be secret; the check is made here, at decode time, before any value exists.

Other file types, same machinery

File kinds are decided by suffix: .tf and .tf.json; override.tf and *_override.tf; .tftest.hcl; .tfquery.hcl; and .tfmigrate.hcl, HCL only (parser_file_matcher.go:19-23, 160-263) from the code. Each has its own schema over the same parser. A test file's top level is run, provider, mock_provider, variable(s), override_* and test {}; a query file's is list, provider, locals and variable. Stacks' .tfcomponent.hcl is a separate implementation in internal/stacks/stackconfig, with stack, component and a two-label provider. .tfdeploy.hcl has no parser in hashicorp/terraform at all; it lives in HCP. Policy files (*.policy.hcl, with resource_policy and enforce) are read by a separate plugin, which Part 4 runs.

Functions: 118 entries and two namespaces

v1.17.0's baseFunctions table has 118 entries by count of the source, and Scope.Functions adds templatefile, templatestring, plantimestamp (not in the console) and type (console only) (internal/lang/functions.go:54-141, 164+) from the code. terraform metadata functions -json lists 119 names, 238 counting the core:: aliases; the two counts use different methods and were not reconciled. Every built-in is also callable as core::NAME, so core::upper("a") is "A", and provider-defined functions are provider::LOCALNAME::FUNC, named by the provider's local name in required_providers measured here. Terraform rewrites HCL's unknown-function errors into "Unknown provider function" with a hint per namespace (internal/lang/eval.go:562-640).

Three edges are worth knowing. convert(value, type) exists since v1.15.0 (#38160) and takes a type expression, as in convert({a=1}, map(string)), although metadata functions does not list it. list() and map() survive only to fail with a migration message; they were removed in v0.15. And the impure functions bcrypt, timestamp and uuid become unknown in scopes that require purity, while filesystem functions are checked for plan-to-apply consistency (functions.go:20-42, 230-234). The built-in provider terraform.io/builtin/terraform adds encode_tfvars, decode_tfvars and encode_expr once it is declared in required_providers.
