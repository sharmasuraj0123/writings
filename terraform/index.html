01A compiler with somebody else's back end

Terraform is a compiler whose intermediate representation is a dependency graph and whose back end is somebody else's process. Each stage hands the next a different data structure: bytes become an HCL syntax tree, the tree becomes a configuration tree, the configuration becomes a resource-level dag.AcyclicGraph, the walk of that graph becomes RPCs to provider processes, and their answers become a plan file and a state document.

Three choices explain most of what follows. Parse without meaning, decode twice. HCL builds a syntax tree with no schema. Terraform decodes the meta-arguments with its own small schemas and keeps the rest of each block undecoded until the provider's schema arrives over gRPC. That is why dynamic "lifecycle" is impossible, why prevent_destroy must be a literal, and why almost every new feature is a new small schema in internal/configs.

The graph is the program. Ordering, parallelism, failure isolation, destroy order and create-before-destroy are edges, not code paths. A vertex runs when its dependencies finish, a failure skips only its dependents, and apply builds a fresh graph from the diff and re-plans every instance with known inputs.

Trust lives in core, data lives outside. Providers are untrusted processes whose answers core checks. Secrets are tracked by marks that may only flow into write-only attributes. The authoritative record is one plaintext JSON document per workspace, and its consistency rests on advisory locks and the backend's own atomic primitive.

The surprises sit where those choices meet the outside world: an S3 backend that has no lock unless one is configured, a terraform_remote_state that strips sensitivity, a policy engine that fails open for plan and apply, and a commercial edge (query, actions, Stacks, Policy) reached through second plugin processes or RPCs that OpenTofu's client never calls. The four parts follow one terraform plan from the bytes on disk to a 36-resource plan on AWS, GCP and Azure.

04Twelve findings

Part 4 closes with the register of all 101 findings. These twelve are the ones the collection is built around. Each carries its class (behaviour that bites users, or a CHANGELOG omission) and its status: measured means reproduced with the v1.17.0 binary, code means read in the pinned source, and verified means an adversarial verifier confirmed it. Each links to the section that shows it.

  1. A1An S3 backend with neither use_lockfile nor dynamodb_table has no lock at all: Lock returns success and locks nothing. behaviour · code, verified Part 3 §02
  2. A2Terraform Policy fails open for plan and apply (an error is printed, the exit code is 0, the run proceeds) but fails closed for init -policies (exit 1). behaviour · measured, verified Part 3 §08
  3. A3terraform_remote_state reads the producer's whole state and drops sensitivity, so a sensitive output prints in cleartext in the consumer. behaviour · measured, verified Part 3 §03
  4. A11plan -destroy -invoke=… is neither converted nor rejected by the CLI, and core answers "Must be in RefreshOnlyMode when invoking actions. This is a bug in Terraform."; the code is unchanged on origin/main. behaviour · measured by a verifier Part 3 §07
  5. A16An error does not halt the walk: only the dependents of the failed vertex are skipped, independent branches still plan, and the partial plan is shown with Errored = true. behaviour · measured and code, verified Part 2 §02
  6. A28terraform init is not offline even with a lock file and a warm cache: default-source installs still ask the registry for versions, and only a filesystem_mirror works with no network. behaviour · measured, verified Part 1 §09
  7. A36A trivial plan starts its provider three times, every alias and every provider-function user adds a process per walk, and the three-cloud plan starts 18. behaviour · measured, verified Part 2 §05
  8. A40Write-only does not mean never sent: core sends the value in every PlanResourceChange and ApplyResourceChange config and only demands that null comes back. behaviour · code and measured Part 3 §06
  9. A44Identity import cannot be unit-tested: mocks refuse imports, and under override_resource core never sets an identity and then fails its own check. behaviour · measured, verified Part 4 §07
  10. A55Once OpenTofu's provider for_each or its state and plan encryption is used, Terraform cannot load that state or plan. behaviour · measured, verified Part 4 §02
  11. C1The v1.17 "dag simplification" rewrite of the walker and AlwaysRunVertex (#39030) are not in the CHANGELOG. CHANGELOG · code, verified Part 2 §02
  12. C4The Policy GA entry cites #38970, a replace-action split; the experiment gate was removed by #38996, and the entry's body was rewritten from "plan, apply, and init" to "plan, apply, and query". CHANGELOG · code, verified Part 3 §08

05Method

Every claim is pinned to hashicorp/terraform v1.17.0 at 018a99c83c5d (21 October 2026) and cited as a file and line, with HCL, go-cty, go-plugin, terraform-plugin-go, terraform-plugin-framework and OpenTofu v1.13.2 pinned the same way. Measurements were made with the v1.17.0 binary on a 2-vCPU Linux box. No cloud credentials existed at any point: the three-cloud project ran on fake credentials, skip flags and mocks, and nothing was applied to a cloud. Counts reproduced exactly; wall-clock times did not, and are given as ranges.

The research went through four adversarial verification passes, and where a verifier corrected or downgraded a claim, the verifier's version is the one printed. A mechanical citation pass then re-checked quoted files and lines against the pinned trees. Nothing in the findings was reported upstream.

The collection follows the house style of Git, taken apart and the Chromium collection: source-first teardowns with measurements, a findings register, and status on every claim.

Provenance. This page summarises the four parts; the part deks are quoted as written and reading times are measured (words in each part's <main> ÷ 225). Each finding is restated from the collection's register with its status, and every section it links to carries the evidence, the citations and what was not verified.
