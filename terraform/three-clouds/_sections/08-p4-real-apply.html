{{S}}What was not run, and the register

Everything so far stopped before a cloud. That was the constraint, not a choice: no AWS, GCP, Azure or HCP credentials existed at any point. So the project's last chapter is a checklist that was written and never executed. It is worth reading for what it says about where the remaining risk sits. The claim of this section: the hard parts left are identity and networking, and no plan can test either.

The real-apply checklist, unexecuted

Setting -var offline=false is the switch. Every fake credential in providers.tf collapses to null, so each provider falls back to its normal credential chain, azurerm switches to use_oidc = true, and the gcp_project validation then demands a real project id. Only that last step was measured, by the test that expects the validation to fail. The rest comes from the project README and provider documentation, and none of it was run or verified here reconstruction:

  • All clouds. A remote backend with locking: S3 with use_lockfile = true, GCS, or azurerm blob leases (Part 3 shows why the S3 switch matters). HCP Terraform is the only route found to real -policies enforcement, and that is inferred from code. When applying a saved plan, re-supply the ephemeral input variables.
  • AWS. CI authentication through GitHub Actions OIDC into a deploy role with sts:AssumeRoleWithWebIdentity; permissions for VPC, S3, RDS, Secrets Manager, IAM and Lambda; a real ECR image instead of the placeholder URI; globally unique bucket names. The Lambda runs in two private subnets with no NAT gateway and no VPC endpoint, so at runtime it cannot reach ECR, Secrets Manager or STS until one is added. Whether a Lambda function error, as opposed to an API error, fails the smoke action and so halts under the default on_failure is unknown.
  • GCP. Workload Identity Federation instead of JSON keys; six APIs enabled (compute, sqladmin, run, secretmanager, iam, servicenetworking); roles/secretmanager.secretAccessor for the Cloud Run service account. Cloud SQL with a private IP needs a private services access range and a google_service_networking_connection, which the module does not model, so a real apply would fail at the SQL instance as written.
  • Azure. OIDC workload identity federation with ARM_CLIENT_ID, ARM_TENANT_ID and ARM_SUBSCRIPTION_ID; real ids in place of the all-zero defaults; the resource providers registered, since the project sets resource_provider_registrations = "none"; Key Vault Secrets Officer for the deploy identity. Purge protection leaves a destroyed vault soft-deleted. The flexible server sits on a delegated subnet with public access off but no private_dns_zone_id, which Azure is believed to require for VNet-integrated servers; the schema says only optional and computed. Whether the /23 Container Apps subnet matches the environment type Azure creates was not checked.

Read the list by kind. Every cloud's first item is an identity federation set-up, and most of the rest is network plumbing: private DNS, private service access, NAT or endpoints, delegated subnets. A plan cannot catch any of it. It checks schemas, types and the graph; it does not ask a cloud whether a subnet can reach a registry or whether a role may assume another. Those are the failures that would appear first on a real apply, and they are the ones this lab could not reach.

Hazards found while building

The one class of failure the lab did hit was local: the shared plugin cache. Terraform has no lock on TF_PLUGIN_CACHE_DIR. Concurrent init runs, including the lab's own credential probe, rewrote all four cached providers twice within about five minutes, and a plan that ran during the rewrite failed its lock-file checksum check. One init that coincided with a rewrite downloaded aws again, about 830 MB, despite a pinned lock file; afterwards all four entries matched the lock's h1: hashes. A verifier's no-lock init in another lab failed "text file busy" because a different process was running the binary it tried to replace measured here. OpenTofu's per-package flock exists for exactly this case (section 2). If several jobs share one cache directory, serialise their init steps.

The thesis, once more

Terraform is a compiler whose intermediate representation is a dependency graph and whose back end is somebody else's process. The four parts followed that sentence from bytes to state. Part 1 showed a parser that builds structure without meaning and a decoder that runs twice. Part 2 showed a graph that is the program and providers that are untrusted processes behind a 36-RPC contract. Part 3 showed a single plaintext document held together by advisory locks, and a decade of features that each arrived as a small schema, a graph node and an RPC. This part showed the same seams from outside. The licence leaves the protocol and the providers open. The fork shares them and diverges everywhere else. The commercial engines run as separate plugins. And a three-cloud project can be validated, tested and planned without a single credential, up to the point where a cloud must answer.
