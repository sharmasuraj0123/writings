{{S}}Compacting a conversation

When an agent's context window fills, the agent replaces older turns with a summary that a model writes: lossy compression of meaning, plus eviction. Storage compactions keep an exact logical state. This one keeps what the summariser judged relevant.

What the vendors document

Claude Code's /compact will "Free up context by summarizing the conversation so far", and it compacts unprompted: "It clears older tool outputs first, then summarizes the conversation if needed. Your requests and key code snippets are preserved; detailed instructions from early in the conversation may be lost." from the docs Models with a native 1M-token window compact "at about 967K tokens by default". from the docs Anthropic's engineering post "Effective context engineering for AI agents" (29 September 2025) describes passing the history to the model "to summarize and compress the most critical details." from the docs Docs read 9 October 2026, when Claude Code 2.1.295 was the latest npm release. from the docs

Its table "What survives compaction" sorts the rest. The project-root CLAUDE.md and auto memory are "Re-injected from disk"; up to five recent files are re-read; path-scoped rules and nested CLAUDE.md files are summarised away, but "Claude Code reloads them on demand"; context that hooks added is "Summarized with the rest of the conversation". from the docs What lives on disk comes back exactly; the rest survives as the summary tells it. reconstruction

The Claude API writes the summary on the server. from the docs Threshold compaction (beta header compact-2026-01-12, strategy compact_20260112) triggers at 150,000 input tokens by default, never below 50,000. On-demand compaction (compact-2026-09-04) returns one block holding "the summary as text you can read, and a signature". from the docs The losses are named: "Images, documents, container_upload blocks, and fetched URLs inside the summarized messages are gone once the block replaces them." from the docs Context editing (context-management-2025-06-27) summarises nothing: it clears old tool results or thinking blocks. from the docs

OpenAI released /responses/compact on 11 December 2025 and server-side compaction on 10 February 2026; its compaction item "is opaque and not intended to be human-interpretable". from the docs Codex's prompt (codex-rs/prompts/templates/compact/prompt.md in openai/codex at 65b82cdf, 9 October 2026) opens: "You are performing a CONTEXT CHECKPOINT COMPACTION. Create a handoff summary for another LLM that will resume the task." from the docs Figure {{fig-context}} puts these rules on one window.

The one compaction without an invariant

Storage compactions state their invariant: the same logical content, or at least the final state of every key (Compaction: keeping only the present). from the docs Context compaction has none. The same Anthropic post: "The art of compaction lies in the selection of what to keep versus what to discard, as overly aggressive compaction can result in the loss of subtle but critical context whose importance only becomes apparent later." from the docs Unlike lossy media coding (Throwing away what nobody sees), it has no distortion metric: no published measure of what these summaries lose was found, and none is measured here. reconstruction

It is the one compaction that needs a human-readable audit trail. A database forgets versions nobody will ask for; an agent's early turns may be wanted later, by a person checking its work. Keep the transcript (stored like any log), record each boundary with its token counts, log each summary, and put durable facts in files, because files come back exactly. reconstruction Claude Code's PostCompact hook exists "to react to the new compacted state, for example to log the generated summary or update external state". from the docs An opaque item can be stored but not audited. In xo-space, the empty fields are where that trail would start. reconstruction
