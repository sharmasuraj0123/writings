{{S}}What each format can say

A data model is the vocabulary of the contract: the values a file can name. JSON is a grammar with almost no semantics. YAML is a serialisation language with a type-resolution step. TOML is a grammar with a small, fixed type system. Each family of pitfalls in this guide follows from one of those designs. reconstruction

JSON: syntax, and almost nothing else

ECMA-404 is explicit in §1: "The goal of this specification is only to define the syntax of valid JSON texts." Its introduction adds: "JSON is agnostic about the semantics of numbers." RFC 8259 adds a little meaning. Readers built on IEEE 754 binary64 agree exactly only on integers within [-(2**53)+1, (2**53)-1], and Infinity and NaN "are not permitted" (§6). Names "SHOULD be unique" (§4). from the spec Readers differ. Of the 10 JSON parsers measured here, nine keep the last of two "a" keys and Go's encoding/json/v2 refuses them. Given {"b": 1, "a": 2, "10": 3, "2": 4}, Python's json and jq keep source order, JSON.parse puts the integer-like keys first, serde_json sorts them (its default map is a BTreeMap), and a Go map keeps no order. measured here JSON's pitfalls are disagreements between readers (the JSON section). reconstruction

YAML: a type for every node

YAML gives every node a tag. A plain scalar gets its tag by matching the schema's regular expressions, and one that matches none is a string (§10.3.2). The 1.2.2 Core schema has six boolean spellings and no timestamp. YAML 1.1 keeps its types outside the spec, in a type repository whose pages are each marked "Working Draft" (2005). Its boolean page lists 22 spellings, from y to OFF; other pages add leading-zero octal, base 60, timestamps and the << merge key. from the spec So the loader, not the file, picks the table: 2001-12-14 is a native date in 6 of the 12 YAML loaders and a string in the other 6. measured here

A %YAML 1.2 directive should settle it, but the research probes found PyYAML 6.0.3 ignoring it: no, 22:22 and 0755 still load as False, 1342 and 493. measured here Keys must be unique (§3.2.1.1). from the spec Which loaders enforce that is measured in the structure you did not see. YAML's tags carry its loader CVEs (When loading means executing). Its pitfalls are type guesses (the type you did not write). reconstruction

TOML: ten types, fixed by syntax

TOML lists ten value types and says "Unspecified values are invalid." Booleans are "Always lowercase." from the spec All 10 TOML parser configurations refuse enabled = True. measured here 1.0 says 64-bit integers "should be accepted"; 1.1 says "Implementations are free to support any integer size." Both make a lossy integer an error. Four date-time types keep an instant apart from a local date-time, which "cannot be converted to an instant in time without additional information." The document is always a table (TOML's rules shows where its root ends). No file can declare its version (TOML 1.1). from the spec What goes wrong is structure: where a key lands and which version the parser reads. reconstruction

The value TOML left out

Issue #30 asked for nil or null and was closed on 24 February 2013 (UTC). Tom Preston-Werner answered: "TOML is intended for configuration, at which point @aaronblohowiak is right: just leave it out." On 7 October 2023 Pradyun Gedam of toml-lang added: "we're not revisiting this design choice at this point". from the docs In #975 (21 May 2023) Armin Ronacher wrote of absence used as null: "I believe this to be a mistake in designing TOML schemas because such a value cannot be represented in TOML." from the docs In layered configuration, absence cannot unset an earlier layer's default. reconstruction x = is an error in all 10 TOML configurations; all 12 YAML loaders read ~, null, empty and Null as null. measured here
