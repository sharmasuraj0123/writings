Every failure in this guide has a guardrail, usually a flag, a schema or a lint rule. The rules below are mine, and each names the failure it prevents. reconstruction

Six rules for any format

1. Name the parser and its version. The format is not the contract; the parser is. The line countries: [GB, IE, FR, DE, NO, SE] gives "NO" in 8 of 12 YAML loaders and false in 4. A multi-line TOML 1.1 inline table is read by 8 of 10 TOML parsers and refused by Python 3.14's tomllib and by @iarna/toml. measured here Write down which library reads the file, pin it, and run it over the file in CI. reconstruction

2. Validate against a schema, in the editor and in CI. JSON Schema serves all three formats: on 8 October 2026, SchemaStore's catalog listed 1,513 schemas, and by file pattern 762 match YAML files, 624 JSON-family files and 128 TOML files. measured here JSON Schema's current dialect, 2020-12, is an Internet-Draft that expired on 12 December 2022. from the spec VS Code warns that an in-file "$schema" key "changes the JSON itself, which systems consuming the JSON might not expect". check-jsonschema 0.38.2 validates all three formats in CI. from the docs

3. Load into a typed target and reject unknown keys. Go's encoding/json documentation says "By default, object keys which don't have a corresponding struct field are ignored". from the docs Turning that off guards the silent structure traps. TOML's scope trap moves debug into server in all 10 parsers, and three YAML loaders return only the first mapping of the file from Helm issue #9793. measured here A Server type with no debug field rejects the first, and required fields report the second. Typed targets were not measured here. reconstruction

4. Reject duplicate keys. All 10 TOML parsers refuse a = 1 followed by a = 2, and so do 9 of 12 YAML loaders; PyYAML's two loaders and sigs.k8s.io/yaml keep the last value. In JSON, 9 of 10 parsers keep the last value silently, and only Go's encoding/json/v2 refuses. measured here A schema cannot catch them: it validates the value the parser returned, after the last duplicate has won. reconstruction

5. Never write human configuration with a non-preserving writer. Load the agent config, change one value and dump it: each of the 21 writers that dump plain data produced 52 to 144 diff lines, and tomlkit and jsonc-parser's modify changed nothing beyond the edit (the write-back test). measured here

6. Keep secrets out of files that agents read and write. An agent reads the whole file it edits, and a dumping writer rewrites it, so keep references such as "${GITHUB_TOKEN}" in the file and the values elsewhere. reconstruction xo-space masks configs sent to the browser only where the value is a string under one of six key names. from the tree In a scratch run, a YAML password: 123456 went out as an unmasked integer. measured here

Rules per format

The flags and tools for each format are in Figure {{fig-checklist}}.

JSON. Keep it strict wherever a program writes it, and use JSONC only through one named parser that fails on errors: jsonc-parser 3.3.1 reports two errors for a trailing comma and still returns {"a": 1, "b": 2}. measured here

YAML. Quote every scalar that is not obviously a string. Unquoted, python: 3.10 is 3.1 in all 12 loaders here; quoted, ten trap values stayed strings in all 16 loader configurations of the research probe. measured here yamllint's truthy rule allows only true and false by default. from the docs Its default check-keys: true also flags a workflow's bare on:. measured here Quote "on" or set check-keys: false for .github/workflows. reconstruction

Load with a safe loader, never an unsafe or full one, that also limits aliases: in Node, eemeli's yaml (maxAliasCount 100); in Go, yaml.v3 (an alias-ratio check); in Rust, serde-saphyr (a node and alias budget) or the archived serde_yaml (a repetition limit). None of the four Python loaders here has one. measured here A cap on input size does not stop a 446-byte bomb. reconstruction js-yaml's safety guide says what does: "do a cheap pass first that counts every element and bails out past a limit". from the docs

TOML. Put top-level keys before the first table, or have none, as Alacritty 0.14 did when it moved its root options into a [general] table (the scope trap). from the docs Write the 1.0 subset unless every reader is pinned: Python 3.14's tomllib and @iarna/toml refuse all four 1.1 features measured. measured here

When none of the three fits

For computed values, types shared across files, or no implicit typing at all, these are the candidates as of October 2026. from the docs

  • JSON5: JSON plus some ECMAScript 5.1 syntax; easier editing, no types (spec 1.0.0, 2018).
  • HCL: HashiCorp's native syntax, with expressions, plus a JSON variant; v2 tagged 2 October 2019.
  • CUE: unifies data with constraints across JSON, YAML and TOML; pre-1.0, v0.17.1 (16 July 2026).
  • Dhall: "JSON + functions + types + imports", not Turing-complete; v23.1.0 (16 January 2025).
  • Jsonnet: templating that emits JSON, v0.22.0 (24 March 2026); by default its imports reach any path the interpreter can read.
  • Nickel: "in essence JSON with functions", with gradual types; 1.18.0 (19 September 2026).
  • Pkl: Apple's configuration language, open-sourced on 1 February 2024; 0.32.1 (23 July 2026).
  • KDL: 2.0.0 (21 December 2024) made bare true, false and null syntax errors.
  • StrictYAML: a Python-only YAML subset, all strings unless a schema says otherwise; 1.7.3 (10 March 2023).
  • NestedText: one scalar type, the string; 3.8 (26 December 2025).
  • Starlark: Bazel's hermetic Python dialect, which needs an embedded interpreter.

ESLint took the last exit. Since v9.0.0 (5 April 2024) its default configuration is eslint.config.js, and v10.0.0 (6 February 2026) removed the old formats. One format, its documentation says, lets it "avoid the need for custom parsing of config files". from the docs Most of these languages emit JSON or YAML, so their output is still parsed and still needs the guardrails. reconstruction

The decision rule

The answer up front, reordered as a flow with a strict-JSON fallback, is four questions asked in order (Figure {{fig-decision}}). TOML gets the hand-edited files because its parsers seldom disagree in silence. reconstruction In cases[].heard, leaving out errors, the agent config and the depth and bomb runs, the parsers that accept a case return two or more readings in 9 of 15 JSON cases, 12 of 26 YAML cases across the 12 loaders, and 4 of 22 TOML cases; TOML's nine other splits are refusals. measured here A refusal is loud. The scope trap is the exception: silent, and the same in all 10 parsers, so it needs rule 3, not a better parser. reconstruction

Whichever box a file lands in, the six rules stay. The format decides which pitfalls are possible. The guardrails decide whether the two readers of the file hear the same thing. reconstruction
