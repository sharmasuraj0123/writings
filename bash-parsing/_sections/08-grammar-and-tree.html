{{S}}The Bison grammar and the COMMAND tree

With the context work done in the lexer, the grammar that remains is small and has no unresolved conflicts. Precedence declarations, not one nonterminal per level, decide the shape of lists and pipelines. The tree is a C tagged union whose words are still unparsed text, and a printer turns any tree back into source, showing what the tree dropped.

The tables

The checked-in y.tab.c is GNU Bison 3.8.2 output with YYNTOKENS 63, YYNNTS 40, YYNRULES 180 (counting $accept) and YYNSTATES 358 (bash/y.tab.c:1037-1048) from the code. The 63 terminals are 3 specials, 11 character literals and 49 names: 48 on %token lines plus yacc_EOF, which enters only through %left (bash/parse.y:389-406, 430) from the code.

Reading those numbers needs three terms. A state is a set of items: rules with a dot marking how much of the right-hand side is already on the stack. The table maps each state and lookahead token to shift, reduce by a numbered rule, or error. A shift/reduce conflict is a state where one lookahead allows both. Bison compares the rule's precedence with the token's, as declared by %left or %right; on a tie the associativity decides, and where either has no precedence "the default is to shift" and the conflict is reported (Bison 3.8.2 manual, §5.2 "Shift/Reduce Conflicts", §5.3.5 "How Precedence Works") from the docs.

lab/scripts/e3_bison.sh rebuilt the parser with bison 3.8.2 in 0.53 s, one run on the shared 2-vCPU lab VM. The result differs from the shipped file in 0 lines outside #line directives. Bison reports no unresolved conflicts, and 45 shift/reduce conflicts resolved by %left/%right (lab/results/e3-bison.txt) measured here. So bash-2.0's "all 66 shift-reduce conflicts are gone" (bash/NEWS:2728-2729) means unresolved ones from the docs.

Precedence instead of levels

Three lines of bash/parse.y, 428-432, settle every list and pipeline from the code: 

%start inputunit

%left '&' ';' '\n' yacc_EOF
%left AND_AND OR_OR
%right '|' BAR_AND

The list rules are ambiguous binary recursions. The top-level ones, as numbered in Bison's report (lab/build/e3/parse.output, Grammar section), are measured here: 

  163 simple_list1: simple_list1 AND_AND newline_list simple_list1
  164             | simple_list1 OR_OR newline_list simple_list1
  165             | simple_list1 '&' simple_list1
  166             | simple_list1 ';' simple_list1
  167             | pipeline_command

list1 inside compound commands has the same shape (bash/parse.y:1286-1306). Between two operators on one %left line Bison reduces, so lists come out left-heavy; the printer's comment says "the parser builds lists to be left-side heavy" (bash/print_cmd.c:330-334). %right '|' makes pipelines right-nested, and execute_pipeline walks down ->second (bash/execute_cmd.c:2641-2642, 2716) from the code. POSIX spends a nonterminal per level (and_or, pipeline, pipe_sequence) and splits a simple command into cmd_prefix, cmd_word and cmd_suffix (XCU §2.10.2) from the docs. bash lets any word, assignment or redirection appear anywhere: >pre echo x prints back as echo x > pre measured here.

The trace of the running example shows the automaton at work. A command-initial WORD enters state 13, which holds two items, so the parser reads one more token before reducing (lab/build/e3/parse.output, State 13, lookahead list trimmed to …) measured here: 

   55 simple_command_element: WORD •  [THEN, ELSE, …, '|', '>', '<', '}', ')']
  101 function_def: WORD • '(' ')' newline_list function_body

    '('  shift, and go to state 85
    $default  reduce using rule 55 (simple_command_element)

With the lookahead AND_AND in state 237, rule 173, the | rule, reduces before && is shifted, which puts && above |. The line's parse takes 18 shifts and 42 reductions (19 and 43 with the next yyparse's yacc_EOF), with the stack at most 7 states deep. Rule 1 ends the parse with YYACCEPT, and $end is never shifted (lab/results/trace-a.txt) measured here. Figure {{fig-precedence}} puts the ladder beside the shapes.

Fix-ups in the actions

yacc groups a; b & as (a; b) &. connect_async_list walks down the ; chain and moves the & onto its last element: "This function takes the `&' and applies it to the last command in the list" (bash/make_cmd.c:820-862) from the code. In sleep 0.5; echo A & echo B the sleep stays in the foreground, about 537 ms in the grammar dossier's run and 518 ms in a rerun of /usr/bin/bash -c here measured here. ! toggles CMD_INVERT_RETURN with XOR, so ! ! cancels (bash/parse.y:1408-1421); ! ! true; echo $? prints 0 measured here. |& becomes a 2>&1 REDIRECT on the left command and a plain '|' connection (bash/parse.y:1473-1496) from the code.

Two constructs bypass the grammar. [[ … ]] is a recursive-descent parser inside read_token that hands Bison one COND_CMD token holding a finished tree: "we slip a mini recursive-descent parser in here" (bash/parse.y:3582-3602, 5251) from the code. ((…)) is one ARITH_CMD only if its matching ) is followed by ). Otherwise its text is pushed back as nested subshells (bash/parse.y:4901-5008), so ((echo a); echo b) prints a and b measured here. §11 covers how [[ ]] is evaluated.

The tree

Every node is a COMMAND with five fields: type, flags, line, redirects and value, a union over 15 command types (bash/command.h:71-73, 197-226). The constructor is bash/make_cmd.c:164-174 from the code: 

make_command (enum command_type type, SIMPLE_COM *pointer)
{
  COMMAND *temp;

  temp = (COMMAND *)xmalloc (sizeof (COMMAND));
  temp->type = type;
  temp->value.Simple = pointer;
  temp->value.Simple->flags = temp->flags = 0;
  temp->redirects = (REDIRECT *)NULL;
  return (temp);
}

Every payload goes in through value.Simple, and the first int of whatever struct it points at is zeroed: a type pun. CONNECTION starts with a dummy int ignore, commented "Unused; simplifies make_command ().", to absorb that write (bash/command.h:229-234). make_command never sets COMMAND.line from the code. The trace prints it as -538976289, which is 0xdfdfdfdf, bash malloc's MEMSCRAMBLE fill (bash/lib/malloc/malloc.c:892-894) measured here. Whether anything reads it is open.

A CONNECTION is binary, so a pipeline has no node type of its own. A SIMPLE_COM holds one flat WORD_LIST of assignments, name and arguments plus a REDIRECT list, and a WORD_DESC is just {char *word; int flags} (bash/command.h:131-140, 337-343). Left-recursive rules prepend, so both lists are built backwards and reversed once: "It seems simpler to do this here the one time" (bash/make_cmd.c:800-818) from the code. The printer

print_cmd.c turns any tree back into text for declare -f, --pretty-print and the comsub word (§07). What it cannot print, the tree did not keep. elif comes back as else if … fi, x |& y as x 2>&1 | y, redirections move after the words, comments vanish, and ! time -p prints as time -p !, because both are flag bits printed in a fixed order measured here with declare -f and --pretty-print on /usr/bin/bash 5.3.9. On all 118 corpus inputs it could print, re-printing the printer's output gives the same text (lab/scripts/e3_roundtrip.py, lab/results/e3-roundtrip-summary.txt) measured here. One-line parse units and error recovery are §09.
