{{S}}Command substitution: a recursive yyparse that keeps only text

Since bash 5.2 the lexer handles $( by calling the real parser again, on the same input, from inside itself. The tree is thrown away; the word keeps only the tree printed back as text. Expansion parses that text again to find where it ends, and the forked child parses it a third time to run it. Backquotes never got this treatment.

The changelog entry of 6/19/2021 reads: "rewrite to recursively call the parser (yyparse()) and return a string constructed from the resulting parse tree. Probably will only work with bison" (bash/CWRU/changelog:1386-1394). It shipped in 5.2 on 2022-09-26. Since 4.0 bash had parsed $( ) only to find its closing delimiter (bash/COMPAT:303-306), and AOSA §3.4's "duplicates rather more of the token-reading code than is optimal" describes that older code from the docs.

Read time: tricking the parser

parse_comsub first peeks one character. Another ( means arithmetic, by POSIX interpretation 217, and it only collects a matched pair (bash/parse.y:4463-4471). Otherwise it sets up a nested parse, bash/parse.y:4499-4549, with block comments trimmed and … marking omitted lines (locals, the funsub flag (a funsub is ${ cmd; }, the in-process form bash 5.3 added, bash/NEWS:57-58), the global_command save, here-doc and counter resets, the BASH_COMPAT extglob block) from the code: 

  save_parser_state (&ps);
  …
  parser_state &= ~(PST_REGEXP|PST_EXTPAT|PST_CONDCMD|PST_CONDEXPR|PST_COMPASSIGN);
  …
  parser_state &= ~(PST_CASEPAT|PST_ALEXPNEXT|PST_SUBSHELL|PST_REDIRLIST);
  parser_state |= PST_CMDSUBST|PST_EOFTOKEN|PST_NOEXPAND;
  …
  shell_eof_token = close;
  …
  if (expand_aliases)
    expand_aliases = posixly_correct != 0;
  …
  current_token = '\n';				/* XXX */
  token_to_read = (open == '(') ? DOLPAREN : DOLBRACE;	/* let's trick the parser ) */
  parsing_command = 1;	/* saved as part of sh_parser_state_t */
  r = yyparse ();

save_parser_state copies the flags, token history, here-doc stack, alias stack, token buffer and even $? (bash/parse.y:7221-7282). It must be done by hand: Bison's LR stacks are locals of yyparse, but yychar and yylval are globals (bash/y.tab.c:1743-1776). DOLPAREN is "never created by yylex" (bash/parse.y:403). The grammar takes it through inputunit's alternative comsub, whose rule is DOLPAREN compound_list ')', and the closing ) arrives as shell_eof_token (bash/parse.y:446-452, 1105-1113) from the code.

The instrumented build shows it on the post's second example, whose first line is: 

cat <<A; echo $(case x in x) echo y;; esac)

Text, not tree

That word is built from the tree, bash/parse.y:4626-4646 from the code: 

  saved_strings = pushed_string_list;
  restore_parser_state (&ps);
  pushed_string_list = saved_strings;

  simplecmd_lineno = save_lineno;

  tcmd = print_comsub (parsed_command);		/* returns static memory */
  retlen = strlen (tcmd);
  if (open == '(')			/* ) */
    {
      if (tcmd[0] == '(')		/* ) need a space to prevent arithmetic expansion */
	retlen++;
      ret = xmalloc (retlen + 2);
      if (tcmd[0] == '(')			/* ) */
	{
	  ret[0] = ' ';
	  strcpy (ret + 1, tcmd);
	}
      else
	strcpy (ret, tcmd);
    }

The space stops a re-print that starts with ( from reading as $((. Then dispose_command frees the tree (bash/parse.y:4672). declare -f exposes the re-print, run on /usr/bin/bash 5.3.9 measured here: 

$ bash -c 'f(){ echo $(echo a   ;   echo b) "${ echo c;}" `echo   d`; }; declare -f f'
f ()
{
    echo $(echo a; echo b) "${ echo c; }" `echo   d`
}

Spacing in $( ) is normalised and the funsub gains a ;. The backquote body keeps its three spaces. In trace (c) the stored word spans four lines in print_cmd.c's layout measured here.

Three parses of one $( )

Figure {{fig-three-parses}} follows the text. At expansion, extract_command_subst calls xparse_dolparen to find where the substitution ends (bash/subst.c:1262-1276). It sets expand_aliases = 0, injects DOLPAREN again and runs parse_string (bash/parse.y:4686-4826). The end comes from rewind_input_string, which backs the string pointer up by the unconsumed tail, under its author's note "need to do more validation on xchars value for sanity -- test cases." (bash/parse.y:1809-1830) from the code. The trace shows parser_state 0x8040 (no PST_NOEXPAND) and a cm_case tree nothing uses measured here.

After the fork, the child strips CTLESC markers, the quoting bytes of §10, with remove_quoted_escapes, turns aliases back on outside posix mode and parses a third time (bash/subst.c:7376-7413) from the code: 

rc = parse_and_execute (string, "command substitution", pflags|SEVAL_NOHIST);

In trace (c) the first two parses run in pid 263985, the third in pid 263987 measured here. Not every $( ) gets three. An unquoted here-doc body skips the read-time parse. $(( and SX_COMPLETE extraction is textual (bash/subst.c:1267-1268). $(<file) can skip the child (§10). ${ cmd; } runs the third parse in-process (bash/subst.c:6925-7117) from the code.

What the extra parses change

A syntax error in $( ) is caught while the line is read, so nothing on the line runs, and bash -n sees it too. Exit status is §09's measured here: 

$ bash -c 'echo before; echo $(if)'
bash: -c: line 1: syntax error near unexpected token `)'
bash: -c: line 1: `echo before; echo $(if)'

Backquotes are still scanned by parse_matched_pair (bash/parse.y:5422), textually since 3.2 (bash/COMPAT:266-271) from the code. A script of echo `for` then echo next passes bash -n; run, it prints the child's syntax error, labelled command substitution: line 1, then next, and exits 0 measured here.

Aliases follow the lanes. With shopt -s expand_aliases, a script that defines f() { echo $(hi); } and then alias hi="echo LATE" prints LATE from f. Under --posix it prints hi: command not found: posix mode expanded aliases at read time, before hi existed measured here.

$(( has a fallback. When chk_arithsub finds unbalanced parentheses, param_expand jumps to comsub (bash/subst.c:10832-10864) from the code. So this passes bash -n and prints hi there, while dash 0.5.12 says Syntax error: Missing '))' measured here: 

echo $((echo hi); (echo there))

POSIX §2.6.3 asks for bash's reading: "shall only parse the expansion as a command substitution if it determines that it cannot" from the docs.
