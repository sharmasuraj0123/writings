{{S}}Is it a keyword? Classifying a word

The grammar sees WORD, ASSIGNMENT_WORD, NUMBER, REDIR_WORD and 22 keyword tokens. Which one a word becomes is decided in C at the end of read_token_word, in a fixed order, each step a POSIX rule that the yacc listing hands back to the lexer. A keyword is a word in command position, nothing more.

The order

When a word ends at an unquoted break character, control reaches got_token. The checks are bash/parse.y:5742-5772, with its five comments trimmed from the code:

Special cases, posix-mode reserved words, aliases if unquoted, default-mode reserved words. A trimmed comment gives the fork's reason: "Posix.2 does not allow reserved words to be aliased". In default mode alias if=echo beats the keyword (§05). Figure {{fig-classify}} draws the sequence.

NUMBER and the special cases

An all-digit word is a NUMBER only if the character that ended it is < or >, or the previous token was LESS_AND or GREATER_AND (bash/parse.y:5727-5740). The comment above says "a `<', or a `&'"; the code tests the two tokens, and the code wins from the code. One line shows all three cases: 

$ bash -c 'echo 2>/dev/null x; echo 2 >/dev/null; echo a2>/dev/null; echo end'
x
end

Only the first 2 is an fd measured here. In the running example that 2 is NUMBER(284), value 2 (lab/results/trace-a.txt) measured here.

special_case_tokens (bash/parse.y:3339-3489) decides in ("Posix grammar rule 6"), do, esac, {, }, -p and ]] from the token history and counters, in the positions Figure {{fig-classify}} lists from the code.

The in of a case sets PST_CASEPAT; while it is set, CHECK_FOR_RESERVED_WORD accepts only esac. esac is not a keyword after | (rule 4) or after (, which the code comments as "phantom Posix grammar rule 4" (bash/parse.y:3181-3184) from the code, added on 2/19/2021 (bash/CWRU/changelog:461-466) from the docs. Right after in it is always ESAC measured here: 

$ bash -c 'case if in if) echo matched-if;; esac'
matched-if
$ bash -c 'case esac in esac) echo E;; esac'
bash: -c: line 1: syntax error near unexpected token `)'
bash: -c: line 1: `case esac in esac) echo E;; esac'

POSIX's pattern_list applies rule 4 to the first pattern word only (XCU §2.10.2) from the docs, so bash is right and brush, which accepts it, is wrong (§13).

Reserved words are a position

CHECK_FOR_RESERVED_WORD (bash/parse.y:3166-3209) matches only a word with no $ and no quoting, where reserved_word_acceptable holds for the previous token. That is the lexer's oracle for command position: a switch of 34 case labels whose default: ignores its argument and reads globals, for a WORD after function or coproc (bash/parse.y:5896-5947) from the code. ARITH_CMD and COND_END joined the list on 2/16/2021 (bash/CWRU/changelog:441-447) from the docs. A match writes state: case sets PST_CASESTMT, esac clears it with PST_CASEPAT, [[ sets PST_CONDCMD. word_token_alist holds 22 words: POSIX's 16 plus select, function, time, [[, ]] and coproc (bash/parse.y:2353-2387). 

$ bash -c 'echo if then fi }'
if then fi }
$ bash -c '{ echo a }'
bash: -c: line 2: syntax error: unexpected end of file from `{' command on line 1
$ bash -c '>/dev/null if true; then echo x; fi'
bash: -c: line 1: syntax error near unexpected token `then'
bash: -c: line 1: `>/dev/null if true; then echo x; fi'

A } after a word is a word, so the brace never closes; after a leading redirection, if is a command name measured here. time_command_acceptable accepts time only after specific tokens and, in posix mode, peeks the raw line to refuse it before a -; the comment cites POSIX interpretation 267 (bash/parse.y:3286-3337) from the code. time -p true under --posix and echo hi | time both give "time: command not found" measured here.

Assignments, declarations, {fd}

Assignments are classified here too: "This is context-dependent, so it cannot be handled in the grammar" (bash/parse.y:5784-5786). assignment() returns the index of = or += after a valid name (bash/general.c:480-537). A passing word gets W_ASSIGNMENT anywhere, and W_NOSPLIT only where assignment_acceptable holds for the previous token; the pair makes it ASSIGNMENT_WORD from the code. LC_ALL=C in the running example has word flags 0x14 = 0x4 | 0x10 (lab/results/trace-a.txt; bash/command.h:78-80) measured here.

A declaration builtin, eval or let in command position sets PST_ASSIGNOK, so the next name=(…) lexes as a compound assignment (bash/parse.y:5799-5818) from the code. declare a=(1 2 3) works, echo b=(1) is a syntax error at (, and command declare c=(7 8) works only under --posix, where command sets PST_CMDBLTIN. Finally, {fd} directly before < or > is a REDIR_WORD, POSIX 2024's optional IO_LOCATION; after exec {fd}>/dev/null, $fd is 10 measured here.
