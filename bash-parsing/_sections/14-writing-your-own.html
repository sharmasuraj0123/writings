{{S}}Writing your own

The implementations amount to a decision list, and each decision has a measured cost. What you build fixes most answers. A shell that executes must match bash's late parsing and its one-command loop. A formatter, linter or editor wants a typed tree of the whole file, and pays in memory and in the inputs where bash defers reconstruction. Figure {{fig-decision-table}} is the list; each paragraph below cites the evidence.

1. Decide when each sub-language is parsed. Eager typed trees catch $(( 1 + )) statically; bash -n does not (§13). But POSIX says $(( is a command substitution when arithmetic cannot parse it (XCU §2.6.3) from the docs, and only bash and brush accept G72 below, which bash runs as hi there; dash, shfmt, OSH, ShellCheck and tree-sitter reject it measured here. Parse eagerly for a tool, but keep each substitution's source text so a fallback stays possible (§07) reconstruction.

2. Decide who owns lexer context, and make it explicit. bash's lexer and grammar actions share globals (§03). OSH passes the mode into Read(lex_mode) and the lexer stores none (oils/frontend/lexer.py:336-363); mvdan's parser sets p.quote; tree-sitter's scanner receives a valid_symbols mask from the code. Any of these lets a test drive the lexer directly reconstruction. It is also the coupling behind Ramey's hand-written-parser regret, quoted in §01.

3. Model here-docs as a FIFO drained at the next newline token. Every working implementation converged on it (§06, §12). Oils got there after retracting a tree walk (§06). tree-sitter keeps the body inside one redirect node, so two bodies on one line, G46, are an ERROR measured here.

4. Handle (( and $(( on purpose. OSH scans the rest of the line with LookAheadDParens for ((; brush backtracks by ordered choice (brush/brush-parser/src/parser/peg.rs:97-130) from the code. Or refuse, and document it, as mvdan's README does, to keep streaming over an io.Reader (§12).

5. Choose an alias policy. Compatibility needs text pushed back inside the lexer: push_string saves the current line and makes the alias text the line (bash/parse.y:2018-2076) from the code. OSH re-parses a built string and cannot do { aliases; brush substitutes at run time, by its own comment a hack (§12). Approximate, and list the failures (§05).

6. If you execute, parse one complete command at a time. POSIX requires it (XCU §2.3, quoted in §09), and it is what lets an alias or shopt on one line change how the next is lexed (§03, §05) reconstruction. Memory stays flat (§13). brush parses whole files, so it forces extglob on "because we parse the entire script with the same settings" (brush-core/src/shell.rs:241-244) from the code.

7. Keep source positions and a printer. A printer gives idempotence tests: bash's is idempotent on all 118 printable inputs, shfmt on 110 of 111 measured here. It also shows what the tree drops (§08). OSH goes further: "the source text can be reconstructed byte-for-byte from this tree" (oils/frontend/syntax.asdl:1-4) from the code.

8. Test differentially against real bash. brush runs 3,209 YAML cases with bash as oracle, 718 marked known_failure. mvdan's syntax tests "confirm parses against bash 5.3, dash, mksh R59, and zsh 5.9" (sh/CLAUDE.md:65) from the docs. OSH's spec suite has 223 files and 3,968 cases, and at least one BUG-bash annotation is stale for 5.3.9 (oils/spec/alias.test.sh:467-478) measured here. Re-run the oracle.

A build order

The decisions fix a shape. Here is one buildable order for a parser meant to execute scripts and also serve tools, assembled from the mechanisms above; each step names what it copies reconstruction.

  1. A line reader with a push-back stack. Hand out one physical line at a time, delete backslash-newline before any token exists, and serve pushed strings before the next refill, as bash's pushed_string_list does for alias text (§02, §05). Record line and column per byte now; positions added later touch every token.
  2. A lexer that stores no mode. The caller passes the mode and gets one token with its span, as in OSH's Read(lex_mode). Start with modes for command words, double-quoted text, arithmetic, here-doc bodies, case patterns and [[ ]]; OSH has 22 at efaa863, so expect the list to grow (§12). Operators are longest match with up to two characters of lookahead, for <<-, <<<, &>> and ;;& (§03).
  3. A recursive-descent command parser. One function per POSIX level, and_or, pipeline, command, simple_command (XCU §2.10.2), as in dash. The parser decides keyword status: a keyword is a plain word it interprets only where a keyword may stand, mvdan/sh's gotStmtPipe and the effect of dash's checkkwd (§12). Assignments, NUMBER and {fd} are tests on the word and the character after it (§04).
  4. A here-doc queue. On <<, append a record with the delimiter and whether any of it was quoted. When the lexer is about to return a newline token, read every pending body raw, in order, ending each on an exact delimiter line (§06). Decide now what an unterminated body is: bash warns, five of the six others reject (§13).
  5. A word parser that recurses. A word is a list of typed parts: literal, quoted, parameter, ${…}, $( ), $(( )), backquote. On $(, call the command parser on the same lexer with ) as its end token, as OSH does, instead of saving globals the way save_parser_state must (§07, §12). On $((, try arithmetic and, if it fails, rewind and parse a command substitution, as XCU §2.6.3 asks and G72 tests. The rewind needs the input buffered back to $((; mvdan/sh refuses the case to stay streaming. Keep every part's source span.
  6. A driver with two loops. To execute: parse one complete command, run it, free it, read on, so an alias or shopt -s extglob takes effect on the next line and memory stays flat (§09, §13). For tools: the same call looped to end of file, collecting the list; then aliases need a policy (§05) and extglob can be forced on, as brush does.
  7. A printer and two oracles. Print any tree back to source and check that printing the re-parse gives the same text, as E3 did for bash (§08). Diff accept/reject against bash -n and against a real run, as E1 did; the two disagree on eight inputs (§13). Start from the ten below.

The four breaks, answered

§01 named four places where "lex the file, then parse the tokens" breaks. Each is one of the decisions above. Keyword status by position is decision 2: bash answers it with shared globals written from 74 sites (§03); the others use a parser-set field, a mode argument, a valid-symbol mask or backtracking. Here-doc bodies as a second mode are decision 3, and every implementation but one converged on the same queue. Nested parsing to find a word's end is decisions 1 and 4: bash parses a $( ) up to three times and keeps only text (§07); the typed-tree parsers parse it once and lose the $(( fallback that G72 needs. Parsing interleaved with running is decision 6: the flat 3.6–5.5 MiB of bash -n and the same-line alias miss are one fact seen twice (§09, §13). Most of the 69 disagreement rows in Figure {{fig-disagreement}} are a place where another parser answered one of these four questions differently reconstruction. So a new shell parser picks its four answers first, from what it is for, and its parsing algorithm second.
