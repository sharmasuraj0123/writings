{{S}}Aliases are text pushed back into the lexer

bash expands an alias by pushing its value back into the lexer's input and lexing it again as source text. So an alias can hold half an if, an unclosed quote or a lone {, an alias defined on a line misses that line, and no other parser reproduces bash exactly.

Ramey: "The bash parser implements aliasing completely in the lexical phase, though the parser has to inform the analyzer when alias expansion is permitted" (aosabook.org/en/v1/bash.html, §3.4) from the docs.

Push, re-read, pop

The check runs at every word end (§04). alias_expand_token is bash/parse.y:3248-3282, with the 8-line OLD_ALIAS_HACK comment block marked … from the code: 

static int
alias_expand_token (const char *tokstr)
{
  char *expanded;
  alias_t *ap;

  if ((parser_state & PST_ALEXPNEXT) || assignment_acceptable (last_read_token))
    {
      ap = find_alias (tokstr);

      /* Currently expanding this token. */
      if (ap && (ap->flags & AL_BEINGEXPANDED))
	return (NO_EXPANSION);
      …
      expanded = ap ? mk_alexpansion (ap->value) : (char *)NULL;

      if (expanded)
	{
	  push_string (expanded, ap->flags & AL_EXPANDNEXT, ap);
	  return (RE_READ_TOKEN);
	}
      else
	/* This is an eligible token that does not have an expansion. */
	return (NO_EXPANSION);

push_string saves shell_input_line and its index on pushed_string_list, marks the alias AL_BEINGEXPANDED and makes the value the current line (bash/parse.y:2018-2076). RE_READ_TOKEN restarts read_token; the parser never sees the alias name. At the end of the text shell_getc returns one synthetic space and sets PST_ENDALIAS, but only if the last character is not a blank, newline or metacharacter and no quote is open. The next call pops (bash/parse.y:2783-2840). The space keeps the alias in use while its last word is checked, so alias echo=echo does not recurse from the code. POSIX §2.3.1 allows it: the shell "may behave as if an additional <space>" from the docs. A value ending in a space or tab gets AL_EXPANDNEXT at definition (bash/alias.c:141-146); pop_string turns it into PST_ALEXPNEXT, so the next word is checked too (bash/parse.y:2096-2099) from the code. What re-lexing text allows

Run with bash -c 5.3.9 and shopt -s expand_aliases; ⏎ is a newline measured here: 

alias hi="echo ALIASED"; hi there         → hi: command not found   (127)
alias hi="echo ALIASED" ⏎ hi there        → ALIASED there
alias q="echo \"open" ⏎ q close"          → open close
alias begin="if true; then" ⏎ begin echo inside; fi   → inside
alias LEFT="{" ⏎ LEFT echo one; echo two; }           → one, two
g() { hi; } ⏎ alias hi="echo LATE" ⏎ g    → hi: command not found
alias if=echo ⏎ if hello                  → hello
eval "alias e3=\"echo e3-ran\"; e3"       → e3: command not found   (127)

Pushed text is classified like source, so the if in begin is a keyword. In E1 (lab/results/e1-matrix.csv, row al03) bash -n, dash, shfmt, OSH, ShellCheck and brush all reject the same alias (named cond there), since -n never runs the alias line; tree-sitter accepts only because it has no reserved words. On LEFT OSH exits 2; ShellCheck v0.11.0 reports SC1089 measured here. g shows a function body binding at definition. alias if=echo works only in default mode, where aliases are checked before reserved words; bash --posix and dash keep the keyword, and posix bash fails with "unexpected end of file from `if'". command_token_position counts PST_REDIRLIST as command position unless the last token was a redirection operator (bash/parse.y:3144-3164) from the code, so >/dev/stderr ll x prints LL x and echo ok > ll writes a file named ll measured here.

The same-line miss is the parse loop: one inputunit, the grammar's start symbol and one complete command (§08), is lexed and parsed before any of it runs (§09), and eval parses its string the same way. POSIX's execute-before-tokenize rule (XCU §2.3, quoted in §01) means alias changes take effect no later than the end of the current complete command (§2.3.1). POSIX 2024 says "it is unspecified whether the TOKEN is subject to alias substitution" for reserved words; Issue 7 forbade it in grammatical context from the docs. bashref says aliases expand "when a command is read" (bash/doc/bashref.texi:8580-8588). That is incomplete: inside $( ) default mode defers to the child, posix mode expands at read time (§07) from the code. (alias_expand() in bash/alias.c is readline's.)

The others move aliases elsewhere. OSH, after parsing a simple command, builds a string and parses it with a new parser (oils/osh/cmd_parse.py:1018-1150). That is its one runtime-to-parser channel, and it cannot do { or for … do aliases. mvdan/sh expands per word in its interpreter and rejects values containing ; (sh/interp/runner.go:505-521). brush expands at run time, "a total hack" (#57) per its comment (brush/brush-core/src/interp.rs:1243). ShellCheck does not expand and tree-sitter-bash has no aliases from the code; only ShellCheck warns, with SC2262, that the alias "can't be defined and used in the same parsing unit" measured here.
