{{S}}Expansion is a second parser

yyparse stops at words. A WORD_DESC reaches the executor spelled as it was in the source, quotes and dollar signs intact. subst.c parses each word again, character by character, every time the command runs. It is a second tokenizer with its own matchers for ${ } and $( ), and it carries quoting through splitting and globbing as marker bytes inside the string. Quote removal is a function that strips them.

Where, and in what order

execute_simple_command calls expand_words on each execution (bash/execute_cmd.c:4605-4617). The work happens in expand_word_list_internal, and its order is fixed in code (bash/subst.c:13219-13279): copy the list; separate the leading assignments; brace expansion; shell_expand_word_list, which is one pass of tilde, parameter, arithmetic, command and process substitution followed by splitting; then glob_expand_word_list, or dequote_list when globbing is off; the assignments last from the code. The manual lists the same stages (bash/doc/bash.1:3372-3384). POSIX has no brace step and says quote removal "shall always be performed last" (XCU §2.6). AOSA calls the expansions "a small pipeline unto themselves" (§3.5.5) from the docs.

In the running example, expand_words receives [LC_ALL=C] [sort] [-u] and returns [sort] [-u] (lab/results/trace-a.txt, lines 367-368) measured here. The assignment is held back and performed after the other words expand, into the temporary environment because a command word remains (bash/subst.c:13270-13273) from the code.

A tokenizer that runs at execution

expand_word_internal (bash/subst.c:11229) is a switch on each character: '\0', CTLESC, < and >, [, =, :, ~, $, backquote, backslash, double and single quote, space (cases at 11331-11933). It returns a list of zero, one or many words from the code. The lexer only brace-matched ${…} (bash/parse.y:5506-5513). The operators inside are parsed here: parameter_brace_expand calls extract_dollar_brace_string, a third } matcher beside the lexer's (bash/subst.c:9865-9893, 10150) from the code.

Brace expansion runs first. The manual says it "is strictly textual" (bash/doc/bash.1:3444-3450) from the docs. The code is not. brace_gobbler lexes quotes, and on $( it calls extract_command_subst, which reaches the yacc parser through xparse_dolparen, to skip over the substitution (bash/braces.c:679-760) from the code. The code wins, and both sides of that are visible: 

$ echo {a,$(echo x,y)}
a x,y
$ n=3; echo {1..$n}
{1..3}

The comma inside $( ) is not a separator, so the result is two words. {1..$n} is not a sequence, because $n is still text when braces run measured here (/usr/bin/bash 5.3.9).

Quoting as bytes

Two marker bytes carry quoting: CTLESC \001 protects the character after it, and CTLNUL \177 marks a quoted empty string (bash/syntax.h:101-102). quote_string prefixes every character with CTLESC; dequote_string inverts it (bash/subst.c:4773-4845). Data cannot pose as a marker, because the lexer escapes a literal \001 or \177 with an extra CTLESC (bash/parse.y:5694-5700) from the code.

lab/scripts/ctlesc_trace.sh builds a copy of the pinned bash that dumps word bytes at four points. It runs in a directory holding the files Xa b, Ya b and Xa bc. For "$x"*'a b'$(echo c) with x=X, lab/results/ctlesc-trace.txt shows measured here: 

  [1 expand_word_internal] flags=0x0 <^AX*^Aa^A ^Abc>
  [2 after split/qnull] flags=0x0 <^AX*^Aa^A ^Abc>
  [3 glob pattern] <X*a bc>
  [4 final argv] flags=0x0 <Xa bc>

The quoted X and every byte of 'a b' are protected. The * and the substitution output c are raw. Figure {{fig-ctlesc}} lays the bytes out. A word is split only if something expanded and W_NOSPLIT is clear (bash/subst.c:13110-13124). string_extract_verbatim skips each CTLESC together with its character (bash/subst.c:1187-1194), so the quoted space never separates from the code. With IFS=:, x=a::b splits into 3 fields. The empty middle one is a CTLNUL word with flags 0x40002 measured here.

lib/glob knows nothing about CTLESC: a grep of lib/glob/*.c finds no occurrence measured here, and its quoting character is the backslash (bash/lib/glob/glob.c:431-447). The translation happens in quote_string_for_globbing (bash/pathexp.c:245-272, four comments trimmed) from the code: 

      else if (pathname[i] == CTLESC)
	{
convert_to_backslash:
	  cc = pathname[i+1];

	    continue;

	  temp[j++] = '\\';

A CTLESC becomes a backslash only before a glob-special character. X, a, space and b are not, so the pattern is X*a bc and it matches the file Xa bc. Quote removal is dequote_string, called inside glob_expand_word_list for a word that does not glob, or by dequote_list (bash/subst.c:12642-12677, 13261-13268) from the code. Results are never re-tokenized: 

$ x="echo hi; echo there"; $x
hi; echo there

What comes back from $( )

read_comsub reads in 4096-byte chunks (COMSUB_PIPEBUF), drops NUL bytes with one warning, "command substitution: ignored null byte in input" (bash/subst.c:6640-6805). comsub_shouldquote quotes every byte inside double quotes, but outside them only the marker bytes (and a space when IFS is null), so unquoted output still splits and globs (bash/subst.c:6643-6662) from the code. $(<file) is a special case. command_substitute parses the text to a COMMAND and checks its shape with can_optimize_cat_file (one input redirect, no words). If it passes, the parent reads the file without forking (bash/subst.c:7160-7168; bash/builtins/evalstring.c:199-208) from the code. The side effect shows, with f0.txt holding hi: 

$ n=0; x=$(<f$((n++)).txt); echo "x=$x n=$n"
x=hi n=1
$ n=0; x=$(cat f$((n++)).txt); echo "x=$x n=$n"
x=hi n=0

With cat, the increment happens in the forked child. ${ cmd; } runs in the current shell through parse_and_execute (bash/subst.c:6925-7138), so v=1; : ${ v=2; }; echo $v prints 2, while : $(v=3) leaves it alone measured here (both blocks: /usr/bin/bash 5.3.9).

Other parsers move this work into the tree. mvdan/sh's Word is a list of 9 WordPart kinds, so expansion walks typed nodes (sh/syntax/nodes.go:564-575), and OSH parses ${…} into a typed BracedVarSub (oils/frontend/syntax.asdl:165-173). brush keeps a Word as raw text and runs a second PEG (parsing expression grammar: ordered alternatives, tried in turn with backtracking) over it at expansion (brush/brush-parser/src/ast.rs:2008-2016) from the code; §12 compares them.
