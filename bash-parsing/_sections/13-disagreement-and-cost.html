{{S}}Where they disagree, and what it costs

On 148 tricky inputs the parsers disagree where a parser must decide when to parse. Late textual parsing makes bash -n accept what static parsers reject. A lexer that reads run-time state makes it reject what runs. Here-documents diverge most. Cost follows the same architecture: parse-one-run-one stays flat, whole-file trees grow linearly, a linter pays two orders of magnitude.

The experiment

lab/scripts/run_e1.py runs each file once through ten parse-only columns, env -i, 10 s timeout. Accept is rc 0 for bash, dash, brush and osh -n and shfmt -ln bash; ShellCheck rejects on any error-level SC1000–1999, tree-sitter on any ERROR or MISSING node. A bash-exec column runs the file: A ran, E run-time error, R parse error. One bit per parser: two can accept and build different trees measured here. All lab numbers come from one shared 2-vCPU VM; differences under about 20% are noise.

All eight unanimous rejects are context-free token errors, such as a lone ; or { echo a }. Of 148, bash -n accepts 123, dash 101, shfmt 119 (pin 121), tree-sitter 110, OSH 117, ShellCheck 116, brush 121 (pin 123); the run gets through 126 without a parse error. Against bash -n: dash disagrees on 30, tree-sitter 29, ShellCheck 21, shfmt 20 (pin 18), OSH 20, brush 18 (pin 16), bash 5.3.9 on none measured here (lab/results/e1-summary.txt).

Late parsing: bash -n accepts what fails

(( 1 + )) and $(( 1 + )) pass bash -n, dash and brush, fail statically in shfmt, OSH, ShellCheck and tree-sitter, and fail in bash at run time. ${x y} passes bash -n, then fails with "bad substitution". x=`if` passes and fails when the run re-parses the body. eval 'if' passes -n in bash, dash, OSH and brush and fails in all four at run time measured here. Each error sits in text bash stored unparsed (§07, §10, §11) reconstruction.

Run-time lexing: bash -n rejects what runs

alias cond='if true; then' followed by cond echo y; fi prints y when run. Every -n rejects it at fi, because none runs the alias builtin (§05); tree-sitter accepts, having no reserved words. shopt -s extglob and, on the next line, echo @(a|b) runs, but bash -n fails at (: the lexer reads extended_glob now (§03). shfmt, OSH, ShellCheck and brush accept extglob regardless measured here. These four rows (al03, al04, eg02, eg04), the four above (ar06, ar07, pe05, qu14) and a NUL-byte row make 9 where bash -n and the run differ. The NUL row, mi03, is a scoring artifact: both exit 126 with the same message. Eight are genuine.

Here-documents

Here-doc rows are 12 of the 69 non-unanimous inputs, the largest group. An unterminated body is a warning in bash and silent in dash; shfmt 3.14.1, OSH, brush, ShellCheck and tree-sitter reject it. POSIX allows both (XCU §2.7.4, quoted in §06). A body ended by EOF) inside $( ) works in bash with a warning (§06); dash, shfmt, OSH, brush and ShellCheck reject it. Seventeen here-docs on one line stop bash with "maximum here-document count exceeded"; no one else has the limit, and tree-sitter rejects sixteen too, since its grammar keeps the body inside one redirect node (§06). Only shfmt and OSH reject <<$X measured here.

(( and line ends

((echo a); echo b) is two subshells to bash, dash, OSH and brush; shfmt, ShellCheck and tree-sitter commit to arithmetic and fail (§08, §12). An &, a backslash-newline and an & make && in bash and dash, which remove continuations below the tokenizer (§02); everyone else rejects it, except brush's pinned parser. A CRLF script fails in bash, dash, OSH, brush and ShellCheck, since fi plus a carriage return is not fi; shfmt and tree-sitter accept it measured here. Versions move bits: shfmt's release and pin differ on two runaway here-docs (hd05, hd10), brush's on lc02 and qu08. Figure {{fig-disagreement}} has all 69 rows.

Speed and memory follow the architecture

lab/scripts/run_e2.py: one warm-up, five timed runs, medians in lab/results/e2-summary.csv. On a 100,000-line script dash takes 0.0537 s and bash 0.1863 s, so dash is 3.5x faster (0.1863 / 0.0537); bash 5.3.9 is within noise. Figure {{fig-speed-memory}}(a) has the rest. Startup-corrected, on bash's 24,753-line configure: dash 1.52 M lines/s, bash 746 k, shfmt 375 k, OSH 194 k, brush 190 k, tree-sitter 60 k, ShellCheck 1.3 k measured here.

Memory separates the designs (run_e2_rss.py, e2-rss.csv). bash -n peaks at 3.6–5.5 MiB and dash -n at 1.7–2.5 MiB on every input. From 10k to 100k lines brush grows from 30.2 to 241.9 MiB, OSH 19.0 to 144.6, tree-sitter 18.6 to 105.3, shfmt 11.7 to 82.3: about 2.5, 1.5, 1.1 and 0.8 KiB per line (241.9 MiB / 100,000 = 2.48 KiB) measured here. Flat is §09's loop, each command disposed before the next is read; sloped is a tree held for the whole file reconstruction. ShellCheck reaches 1,855 MiB, about 19 KiB per line: 654x slower than bash -n (121.7977 / 0.1863) with 386x the memory (1,855 / 4.8) measured here; with no parse-only mode, that prices its checks too reconstruction.

lab/scripts/e4_incremental.py (median of 7) prices an editor. tree-sitter parses a 4,992-line file with 192 here-docs in about 97 ms. A one-byte edit in a body or a word reparses in about 2 ms, 48x faster. Breaking a here-doc tag costs 16–23 ms, and the changed range runs to EOF. tree-sitter then reports one ERROR and keeps 101 of 192 bodies; bash reads to EOF as the body and fails on an unclosed { measured here.
