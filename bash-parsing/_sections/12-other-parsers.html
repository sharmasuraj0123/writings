{{S}}Six other ways to write a shell parser

Every shell parser answers two questions. Who owns the lexer's context? When is each sub-language parsed: $( ), arithmetic, ${ }, here-doc bodies, aliases? Bash answers shared globals, and late, as text. The answers predict what each parser accepts and costs (§13).

Lineage

Thompson's V6 shell read a whole line into words, then parsed (Research-V6:usr/source/s2/sh.c:152-163) from the code: the last clean lex-then-parse split. Nothing depended on position; if and goto were separate programs from the docs (Wikipedia, "Thompson shell"). Bourne's V7 sh (version string 1978-11-06) is recursive descent in C, dressed as ALGOL 68 by mac.h. term() does reserv++, and word() checks keywords only while reserv is set, clearing it after every token (Research-V7:usr/src/cmd/sh/word.c:45-67, cmd.c:128-142). comsubst() parsed backquoted text during expansion (macro.c:168-185) from the code. Tom Duff wrote that "nobody really knows what the Bourne shell's grammar is", because its routines "all have a flag argument that subtly changes their operation" (doc.cat-v.org/plan_9/4th_edition/papers/rc). KornShell contributed $( ), (( )), [[ ]] and ;&. POSIX.2 published the first grammar in 1992 (XRAT §C.2.6.4, §C.2.9.4; bash/POSIX:12-19) from the docs. Figure {{fig-technique-map}} places the six beside bash and V7.

dash: a flag channel

dash keeps the V7 shape: one C function per level, list, andor, pipeline, command, simplecmd (dash src/parser.c:116-120, master 49f04dd). Before each readtoken() the parser sets a three-bit checkkwd, CHKALIAS|CHKKWD|CHKNL, keyword before alias (src/parser.h:72-74; src/parser.c:181-182). Unlike bash, it parses $( ) with a recursive list(2) at lex time and keeps the tree (src/parser.c:1523-1636) from the code. It is the fastest parser measured, 0.054 s for 100,000 lines, peak RSS flat at 1.7-2.5 MiB. It accepts 101 of 148 tricky inputs, rejecting mostly bash extensions measured here.

mvdan/sh: the parser tells the lexer

mvdan/sh is streaming, non-backtracking recursive descent in Go over an io.Reader, read in 1 KiB chunks (bufSize = 1 << 10, sh/syntax/parser.go:575). The parser sets p.quote to one of 21 single-bit states, and preNested saves it around nested constructs, the job save_parser_state does in bash (sh/syntax/parser.go:681-741; … marks omitted states, comments and masks):

func (p *Parser) preNested(quote quoteState) (s saveState) {
	s.quote, s.buriedHdocs = p.quote, p.buriedHdocs

Keywords are plain _LitWords, interpreted only at statement start by gotStmtPipe (2245-2323) from the code. The README states the price: "$(( and (( ambiguity is not supported. Backtracking would complicate the parser and make streaming support via io.Reader impossible" (sh/README.md:71-78) from the docs. So ((echo a); echo b), two subshells in bash, fails in shfmt v3.14.1 with "not a valid arithmetic operator" measured here.

Oils/OSH: the mode is an argument

OSH's lexer stores no mode. The caller passes it on every call (oils/frontend/lexer.py:336-349, the first 14 lines of Read): 

    def Read(self, lex_mode):
        # type: (lex_mode_t) -> Token

        # Inner loop optimization
        if self.src_line:
            line_str = self.src_line.content
        else:
            line_str = ''
        line_pos = self.line_pos

        tok_type, end_pos = match.OneToken(lex_mode, line_str, line_pos)
        if tok_type == Id.Eol_Tok:  # Do NOT add a span for this sentinel!
            # LineLexer tells Lexer to read a new line.
            return self.eol_tok

Each mode is a regex list; lexer_gen.py emits one switch (lex_mode) with a re2c DFA per mode (274-322). re2c compiles regular expressions into C state machines, so a mode is literally a different automaton. At efaa863 there are 22 modes plus Undefined, under a comment that still says "Fifteen lexer modes for OSH" (oils/frontend/types.asdl:10-39). The only lexer state is a hint stack: $( makes the next ) an Eof_RParen (lexer.py:420-498). A $( ) is a new CommandParser on the same lexer and line reader, no text copied (oils/osh/word_parse.py:1207-1233). Arithmetic is a Pratt loop, top-down operator precedence in which each operator token carries a binding power and the loop keeps folding while the next operator binds tighter (oils/osh/tdop.py:286-313); the tree is lossless (oils/frontend/syntax.asdl:1-4) from the code. Text is re-parsed in "4 places": here-docs, a[x+1]=, backticks, aliases (oils/doc/parser-architecture.md:86-124) from the docs. OSH executes one logical line at a time; only osh -n, tools and trap parse whole files (oils/core/main_loop.py:1-10; oils/builtin/trap_osh.py:296). 100,000 lines take 1.52 s and 144.6 MiB measured here. Figure {{fig-osh-modes}} shows the modes on one line.

ShellCheck: no lexer at all

ShellCheck's parser is one 3,673-line Haskell module over ParsecT String, with no token stream. Parsec is a parser-combinator library: each grammar rule is a Haskell function that consumes characters, and rules compose by sequence and alternative (shellcheck/src/ShellCheck/Parser.hs:56-57). The linefeed combinator itself reads pending here-doc bodies (60-66). Ambiguity is resolved by backtracking: readAmbiguous tries the expected parse, then the alternative, and notes SC1102 or SC1105 if it won (1689-1700; the notes at 1637, 2882). The undecidable a[k] is re-parsed after the fact, as a string key if a declare -A (or local, typeset) of the name appears anywhere in the file (3558-3602; ASTLib.hs:630-649). A real syntax error yields no AST (prRoot = Nothing), only SC1072, SC1073 and SC1009 (3494-3556) from the code. Linting 100,000 lines takes 121.8 s and 1,855 MiB measured here.

tree-sitter-bash: the generated parser asks the lexer

A 1,201-line grammar.js generates a 350,631-line parser.c with STATE_COUNT 7571 (tree-sitter-bash/src/parser.c:17-24). tree-sitter generates GLR tables, generalized LR: where the grammar declares a conflict, the parser forks and runs both readings until one dies. bash's grammar declares six, among them [$.command, $.variable_assignments] (grammar.js:47-54). The generated lexer looks only for tokens valid in the current state. The rest goes to a 1,217-line external scanner handed a valid_symbols mask: here-doc pieces, _concat, variable_name, regexes, extglobs (src/scanner.c:9-39). For incremental reparsing its here-doc stack must serialize into at most 1,024 bytes each time the scanner recognises a token (src/tree_sitter/parser.h:14; scanner.c:87-155) from the code. Error recovery always yields a tree, with ERROR nodes. It accepts 8 inputs bash -n rejects, including echo a; }, and rejects 21 that bash accepts measured here.

brush: tokenize everything, then PEG

brush's tokenizer knows no grammar and emits only Operator and Word tokens (brush/brush-parser/src/tokenizer.rs:45-50) and reorders the stream so each here-doc body follows its tag (513-648). A peg 0.8.6 grammar whose rules mirror POSIX §2.10 then backtracks over the tokens: compound_command tries arithmetic_command before subshell, and an unmatched ) means "we need to backtrack" (src/parser/peg.rs:97-130). Words, arithmetic and comsub bodies stay strings until expansion. Parsing the whole file first, brush forces extglob on (brush-core/src/shell.rs:241-244) and expands aliases at execution, "a total hack" (src/interp.rs:1243) from the code. A syntax error after exit 0 makes brush run nothing; bash, dash and OSH run up to the exit. 100,000 lines take 0.865 s and 241.9 MiB, ~2.5 KiB a line measured here.
