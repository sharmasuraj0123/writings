{{S}}The lexer that knows where the parser is

Bison pulls bash's tokens one at a time from inside yyparse. Each decision the lexer makes depends on state that the lexer and the grammar actions both write. State flows in both directions, and the grammar can stay small because this channel exists.

yylex is a wrapper with a memory

The function Bison calls is short. It is bash/parse.y:3054-3094 from the code, with the 9-line mailbox check and the 5-line YYERRCODE block marked …, and two comments trimmed: 

static int
yylex (void)
{
  if (interactive && (current_token == 0 || current_token == '\n'))
    {
      …
      if (token_to_read == 0 && SHOULD_PROMPT ())
	prompt_again (0);
    }

  two_tokens_ago = token_before_that;
  token_before_that = last_read_token;
  last_read_token = current_token;
  current_token = read_token (READ);

  if ((parser_state & PST_EOFTOKEN) && current_token == shell_eof_token)
    {
      return (current_token);
    }

  if (current_token < 0)
    …
  return (current_token);
}

It prompts at a command boundary, shifts a three-token history and calls read_token. The history also moves in push_token, whose only caller is bash/builtins/evalfile.c:333, a fake newline after a sourced file that ends at EOF. parse_compound_assignment calls read_token without shifting at all from the code.

read_token checks one slot before any input (bash/parse.y:3569-3580): 

if (token_to_read) { result = token_to_read; …
      token_to_read = 0; … return (result); }

The slot carries '\n' after an error or after a bare time, COND_END after a [[ … ]], and the synthetic DOLPAREN and DOLBRACE tokens that open nested parses (§07) from the code. Operators are hand-coded if/switch blocks with one or two characters of lookahead, for <<-, <<<, &>> and ;;& (bash/parse.y:3688-3762). other_token_alist (2389-2425) exists only to name tokens in error messages. Character classes come from the generated sh_syntaxtab; the metacharacters are ()<>;&| (bash/syntax.h:29-32, 73-75). # starts a comment only at the start of a token: bash -c 'echo a#b #c' prints a#b measured here.

Three stores of context

First, the token history. Second, counters: open_brace_count, esacs_needed_count, expecting_in_token, and the 256-deep compoundcmd_lineno stack (MAX_COMPOUND_NEST, bash/parse.y:344-359). Grammar actions read it for the start line of for, select and case commands (bash/parse.y:895-1049); the EOF error reads it to name the open construct in "unexpected end of file from `while' command on line 1" (6892-6902) from the code. Third, parser_state: one int holding 28 PST_* flags, five of them commented unused (bash/parser.h:29-56). bash's own DEBUG printer, dump_pflags, tests 27 of the 28; it skips PST_FORCMD from the code. Flags outlive their code: 11 of 16 LEX_* flags are dead leftovers of the pre-2021 scanner for command substitutions (comsubs, bash's own abbreviation for $( )), present only in their #define and the debug printer (bash/parse.y:3835-3850) from the code.

Both sides write these stores. The lexer sets flags while recognising text. ;;, ;& and ;;& set PST_CASEPAT (bash/parse.y:3709-3718, 3757-3761). A ( outside a pattern list or [[, not after a WORD, sets PST_SUBSHELL and pushes compoundcmd_top. A ) after WORD ( sets PST_ALLOWOPNBRC, so the next { opens a function body (bash/parse.y:3765-3791). Keyword matches set PST_CASESTMT and PST_CONDCMD (§04) from the code.

The grammar writes back. make_simple_command sets PST_REDIRLIST when it starts a fresh command and clears it when the first word arrives (bash/make_cmd.c:480-490). The lexer reads that bit to decide whether a word after a leading redirection is in command position. Loop actions pop compoundcmd_top, which the lexer pushed (bash/parse.y:904-905). The timespec actions plant token_to_read (bash/parse.y:1436-1442). A grep for parser_state |=, &= and = outside the generated y.tab.c finds 74 sites: 71 in parse.y, 3 in make_cmd.c measured here. On error reset_parser zeroes parser_state and the counters, frees the line and plants token_to_read = '\n' (bash/parse.y:3494-3539) from the code.

Ramey describes the channel from the parser's side: "the parser has to tell it something about how far it has progressed parsing a command" (aosabook.org/en/v1/bash.html, §3.4) from the docs. Figure {{fig-feedback-loop}} draws the loop.

Watching the bits move

The running example needs none of this. Its trace prints parser_state=0x0 at all 19 yylex returns, 18 tokens plus yacc_EOF (lab/results/trace-a.txt) measured here. The token history alone classifies it; PST_REDIRLIST is set and cleared inside one make_simple_command call, between two trace lines.

A case makes the flags visible. Trace (c) prints the state after each token of $(case x in x) echo y;; esac) (lab/results/trace-c.txt). The three comsub bits, 0x408040, are constant. CASE adds PST_CASESTMT (0x4080c0). IN adds PST_CASEPAT (0x4080c1). The pattern's ) clears it, ;; sets it again, and ESAC clears both measured here. Figure {{fig-pst-strip}} plots the eleven columns.

State the parser never sees

The lexer also reads globals that only executing a command can change. With extglob, @( is lexed as the start of one pattern word, but only if extended_glob is on at the moment the word is read (bash/parse.y:5464-5466) from the code: 

#ifdef EXTENDED_GLOB
      /* Parse a ksh-style extended pattern matching specification. */
      if MBTEST(extended_glob && PATTERN_CHAR (character))

bash parses a whole line before running it (§09), so on one line shopt runs too late: that is the syntax error near ( shown in §01. On two lines the script runs and prints @(a|b); no file matches. bash -n rejects even the two-line form with rc=2, because -n never executes shopt; bash -O extglob -n accepts it (lab/results/tricky.txt; reproduced with /usr/bin/bash 5.3.9) measured here. A syntax check that does not run the script cannot know which language the script is written in reconstruction.
