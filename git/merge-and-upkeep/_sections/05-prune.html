{{S}}Deleting by the clock

Adding objects needs no lock, because an object never changes (Part 1). Deleting them is harder. git prune cannot lock out every process that might be about to reference an object, so it uses time instead. It deletes an unreachable loose object only if the file's mtime is older than --expire, two weeks by default since v1.5.5 (25ee9731c1). Its roots are the index, every ref, every worktree's HEAD and every reflog entry. Since v2.2.0 (d3038d22f9) it also keeps anything reachable from a recent unreachable object, so a tree written a minute ago keeps an old blob alive (builtin/prune.c:84-109) from the code.

The clock only works if writers reset it. When a writer finds that an object it wants to write already exists, it "freshens" it instead: utime() on the loose file, or on the whole pack. packfile.c:2172-2186: 

int packfile_store_freshen_object(struct packfile_store *store,
				  const struct object_id *oid)
{
	struct pack_entry e;
	if (!find_pack_entry(store, oid, &e))
		return 0;
	if (e.p->is_cruft)
		return 0;
	if (e.p->freshened)
		return 1;
	if (utime(e.p->pack_name, NULL))
		return 0;
	e.p->freshened = 1;
	return 1;
}

A pack is touched once per process. A cruft pack is never touched, because its per-object mtimes live in a .mtimes file; returning 0 makes the caller write the object loose again, with a fresh mtime. Both paths showed up in the lab. Rewriting an old loose blob reset its mtime and took it off prune -n's list, and rewriting a cruft-packed blob produced a new loose file measured here.

The manual is candid about what is left. Users "who run commands concurrently have to live with some risk of corruption (which seems to be low in practice)" (Documentation/git-gc.adoc:167-169). And since gc and the maintenance reflog task both expire reflogs, their roots were thinned by a v2.50.0 regression: the built-in defaults expire all entries after 30 days and unreachable ones after 90, the reverse of the documentation (reflog.h:25-28). It was reported and fixed upstream after the v2.55.0 tag by 60cf500551, which is on master but in no release yet (finding A1). Reflogs themselves are covered in Part 2, and worktree pruning in One repository, many agents.
