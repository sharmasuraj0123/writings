{{S}}The findings register

Reading v2.55.0 line by line against its manual turns up mismatches. Figure {{fig-register}} lists all of them, in four groups. Group A is three real bugs in v2.55.0 that upstream has already fixed after the tag: the fixes are on master, next and seen but in no release yet. None of them was found here; each was reported or fixed upstream, and the register records the introducing commit, the fix and a reproduction. Group B is five latent bugs or gaps still present at origin/seen as fetched on 21 October 2026. Group C is 29 places where the documentation and the code disagree; the code wins. Group D is behaviour that is documented, or deliberate, but surprises people.

The reproductions for A1, A2, B1, B2, B3 and D1 were re-run for this post with git version 2.55.0, and each printed what the register says measured here. The others come from the dossier's lab runs and the verification passes behind it.

Upstream keeps moving, and a few changes since the tag touch rows below. On master: USE_NSEC became the runtime setting core.useNanosec (3a21fe8cf9, D24), reftable's reflog timezones were fixed (e14e2b6cf2), and init.defaultRefFormat was renamed init.defaultRefStorageFormat (53d995c53f). Only on seen, core.indexLockTimeout (fd1a1fc743) would let the index lock wait (D19). None is in a release yet.

Read by subsystem, the register follows the collection's thesis. Git is an append-only store of objects surrounded by a few small mutable files, and each file is either a pointer or a cache with its own consistency story. Objects need no lock, and no finding touches how an object is named or stored. Mutable files publish by rename, and two of the fixed bugs sit at that edge: reflog expiry, which decides what a pointer's history protects, and the shallow-clone section order on the wire. The rest cluster around derived data: the index as a cache (B1, B2, C2), the commit-graph and its filters (A3, B5, C10, C11, D2, D11), packs and their indexes (C3 to C7) reconstruction.

That is where git's surprises live: where one consistency story meets another. A cache whose freshness test is a timestamp. A ref backend atomic per ref, not per transaction. A deletion that relies on a two-week clock and on writers touching mtimes. Publishing that is atomic but, by default, not durable. Merging and upkeep add no new kind of state. They add objects, rebuild what can be rebuilt, and wait for the clock before throwing anything away.
