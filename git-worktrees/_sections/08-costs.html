{{S}}What a second checkout costs

I timed six ways to give an agent its own checkout of git.git at v2.55.0, three runs each. Four of them finish in about a second and add about 60 MB, which is the size of the checked-out files. The two that transfer a pack take 30 to 60 times longer. A sparse worktree beats them all.

How the numbers were taken: lab/costs.sh ran each method three times on a 2-vCPU box, against the pinned clone in ~/git-ref/src, which has one 320 MiB pack measured here. "New disk" is du -sk of the new directory plus, for worktrees, the 0.5 MB admin entry. The exception is the hardlinked clone, where du run on the source and the clone together showed 712 KB of new .git. The individual runs, in ms: full clone 62,441 / 61,916 / 59,810; blobless 34,578 / 33,006 / 32,939; worktree 1,026 / 823 / 1,218; sparse worktree 304 / 291 / 517.

Disk use is the more important number. Ten agents on ten full clones of this repository would use about 3.7 GB, and ten worktrees about 0.6 GB. Ten sparse worktrees limited to Documentation/ would use about 0.17 GB. That is arithmetic from the medians, not a measured run of ten. On a box with 9 GB free, which is this one, that difference decides how many agents fit.
