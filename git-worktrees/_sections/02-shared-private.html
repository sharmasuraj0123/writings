{{S}}What is shared and what is private

A linked worktree has two directories behind it: its own small admin directory under .git/worktrees/<name>/, and the main repository's .git, which git calls the common directory. Every path git resolves inside .git goes to one of the two, and a short hard-coded table decides which.

The table is common_list in path.c:98-124 from the code. Each row has three flags: whether the path is ignored by garbage reporting, whether it is a directory, and whether it belongs to the common directory (the struct is at path.c:89-96). Lines 98-123, verbatim: 

static struct common_dir common_list[] = {
	{ 0, 1, 1, "branches" },
	{ 0, 1, 1, "common" },
	{ 0, 1, 1, "hooks" },
	{ 0, 1, 1, "info" },
	{ 0, 0, 0, "info/sparse-checkout" },
	{ 1, 1, 1, "logs" },
	{ 1, 0, 0, "logs/HEAD" },
	{ 0, 1, 0, "logs/refs/bisect" },
	{ 0, 1, 0, "logs/refs/rewritten" },
	{ 0, 1, 0, "logs/refs/worktree" },
	{ 0, 1, 1, "lost-found" },
	{ 0, 1, 1, "objects" },
	{ 0, 1, 1, "refs" },
	{ 0, 1, 0, "refs/bisect" },
	{ 0, 1, 0, "refs/rewritten" },
	{ 0, 1, 0, "refs/worktree" },
	{ 0, 1, 1, "remotes" },
	{ 0, 1, 1, "worktrees" },
	{ 0, 1, 1, "rr-cache" },
	{ 0, 1, 1, "svn" },
	{ 0, 0, 1, "config" },
	{ 1, 0, 1, "gc.pid" },
	{ 0, 0, 1, "packed-refs" },
	{ 0, 0, 1, "shallow" },
	{ 0, 0, 0, NULL }

Read the third column. A path is shared when it, or the nearest listed directory above it, has a 1 there. objects, refs, config, hooks, packed-refs and rr-cache are shared. Inside the shared refs directory, three subtrees are carved back out as private: refs/bisect, refs/rewritten and refs/worktree. So is info/sparse-checkout, which lets each worktree have its own sparse patterns (§07). Anything not in the table at all, such as HEAD, index, ORIG_HEAD, MERGE_HEAD and the rebase-merge/ state directory, defaults to private. reconstruction of the lookup from the trie code that follows the table.

The ref store makes the same split by name. refs.c:881-886 from the code: 

int is_per_worktree_ref(const char *refname)
{
	return starts_with(refname, "refs/worktree/") ||
	       starts_with(refname, "refs/bisect/") ||
	       starts_with(refname, "refs/rewritten/");
}

Root refs count as per-worktree too. is_current_worktree_ref (refs.c:941-943) accepts any all-caps name such as HEAD, ORIG_HEAD or AUTO_MERGE. Everything else, notably every refs/heads/* branch, every tag, every remote-tracking ref and refs/stash, is shared. A worktree can still read another worktree's private refs by spelling them worktrees/<name>/refs/worktree/... or main-worktree/HEAD (parse_worktree_ref, 945-991) from the code.

I checked this on a hub with four worktrees measured here. A ref written in wt1 as refs/worktree/mark was invisible to for-each-ref in wt2. In wt2, git rev-parse worktrees/wt1/refs/worktree/mark resolved it to e9019fcafe. A branch written in wt1 showed up in wt2 immediately.
