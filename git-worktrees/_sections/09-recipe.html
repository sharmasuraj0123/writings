{{S}}A recipe for N agents

Everything above comes down to a short procedure. A supervisor owns the hub repository. Each agent gets a locked worktree on its own namespaced branch, with its own config, and never uses the stash. When it finishes, the branch is pushed and the worktree removed. Figure {{fig-recipe}} shows the lifecycle.

Once per hub

git config extensions.worktreeConfig true      # lets step 2 stay private
git worktree prune                             # clear entries left by crashed agents
mkdir -p ../wt

Per agent

id=7; b="agent/$id/fix-login"; wt="../wt/agent-$id"
git fetch origin
git worktree add --lock --reason "agent $id" -b "$b" "$wt" origin/main
git -C "$wt" config --worktree user.name  "agent-$id"
git -C "$wt" config --worktree user.email "agent-$id@example.invalid"

# … the agent works in "$wt": edit, git add, git commit (never git stash) …

git -C "$wt" push --force-with-lease -u origin "$b"
git worktree unlock "$wt"
git worktree remove "$wt"          # refuses if anything is uncommitted

I ran this in the lab hub, with a local bare remote standing in for origin measured here. The agent's commit was authored by agent-7 <agent-7@example.invalid>, while the hub's user.name stayed lab. worktree list showed [agent/7/fix-login] locked. Removing it before unlocking failed with "cannot remove a locked working tree, lock reason: agent 7". After unlocking, an untracked tmp.txt still blocked removal. Once that was deleted, remove succeeded and the entry was gone.

The rules behind it

  • One branch per agent, under a namespace. Branches are shared (§02), so agent/<id>/… keeps one agent from reusing another's name, and Rule 1 (§04) keeps two agents off one branch.
  • No stash. refs/stash is shared (P2). An agent that runs stash pop can apply another agent's work. Commit WIP to the agent's branch and squash it later.
  • Identity and hooks per worktree. With extensions.worktreeConfig, config --worktree keeps author names and core.hooksPath out of other agents' worktrees (P4).
  • Guarded updates only. Use --force-with-lease, or update-ref <ref> <new> <old>, so a lost race fails (P10) instead of overwriting the winner.
  • Lock while running, prune on startup. A lock protects a worktree from prune. Startup prune clears what crashed agents left, which would otherwise hold their branches for three months (§06).
  • Dependencies are not shared. node_modules/, target/ and virtualenvs are ignored files inside each worktree. Each agent rebuilds them, and §08's numbers don't include them. A shared package cache (pnpm's store, CARGO_TARGET_DIR, uv's cache) is how you share that cost; git plays no part. reconstruction
  • Ports, databases and env files are not git's job. A worktree keeps agents' checkouts apart and nothing more.
