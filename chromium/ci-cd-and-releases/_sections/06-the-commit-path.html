{{S}}The commit path, upload to tryjob

Between a keystroke and a running tryjob sit five machines and two presubmit runs. Which tryjobs run is decided by a generated file, not by a person, and most of them do not run at all: the second time you ask, the answer is a build somebody else already paid for.

§§02–05 were the supply side: the fleet, standing there, configured. The next four sections are the demand side, one change at a time. Figure {{fig-commit-path}} is the whole path on one page. git cl upload shells out to presubmit_support.py --upload under vpython3, then pushes the squashed commit to Gerrit's magic ref refs/for/<branch>%<opts> (git_cl.py:1935–1996, 7205–7218) from the tree. New changes are work-in-progress unless you pass --send-mail. The %-suffix is where the flags go: -c and -d become label votes in a push option. depot_tools/git_cl.py:2245–2253 is the whole mechanism:

git cl try with no arguments just votes Commit-Queue+1. With -B luci.chromium.try -b <builder> it skips the queue entirely and calls Buildbucket's ScheduleBuild itself, tagging every request user_agent: git_cl_try (git_cl.py:437–490, 8112–8124). That path has no quota. The docs ask for no more than about five to ten tryjobs per builder per hour, and say why: "we don't have per-user quotas yet" (docs/infra/trybot_usage.md:25–29) from the docs.

Two presubmit runs, one script

src/PRESUBMIT.py declares PRESUBMIT_VERSION = '2.0.0' on line 23. Under that protocol presubmit_support runs every global function whose name starts with Check, skipping the ones ending in Commit on upload and the ones ending in Upload on commit (presubmit_support.py:1797–1811). The file is 8,937 lines and defines 95 top-level checks (grep -c '^def Check' at f288fed6). Banned patterns are BanRule dataclasses. CheckUnwantedDependencies runs checkdeps over newly added include lines, erroring on - rules and warning on !. CheckTodoBugReferences rejects any TODO whose bug id is at or below 1524553, Monorail's last id. CheckTreeIsOpenOnCommit asks chromium-status whether the tree will take a commit at all. depot_tools hard-codes Chromium's holiday infra freezes as datetime literals — 2025-11-21 to 11-30 and 2025-12-19 to 2026-01-04, Pacific — bypassable only with Ignore-Freeze (presubmit_canned_checks.py:1179, 1184–1195).

Your workstation is not trusted to have run any of this. Two CQ builders, linux-presubmit and win-presubmit, run the same scripts again in the cloud on recipe presubmit: a 40-minute build timeout, an 8-minute presubmit step timeout, priority 25 against Buildbucket's default 30, and on_default_cq (try/presubmit.star:27–31, 178–220); the generated config gives both of them disable_reuse: true, so a presubmit build is never adopted from an earlier run (commit-queue.cfg:6383–6384 and 8735–8736). The recipe passes --commit --skip_canned CheckTreeIsOpen, because CV owns the tree check itself (depot_tools/recipes/recipe_modules/presubmit/api.py:176–194). What it does with the output is the part worth naming. upload_findings_from_result walks the presubmit step's JSON and turns its errors, warnings and notifications lists into Finding protos of category="chromium_presubmit" at SEVERITY_LEVEL_ERROR, _WARNING and _INFO. Each one carries a Location.GerritChangeReference — host, project, change, patchset — plus the file_path and the start and end line and column the check reported, then goes up in one upload_findings call (api.py:242–288) from the tree. That is why a presubmit complaint appears against the line it is about rather than as a wall of text: the coordinates were in the proto. A check that returns no locations gets no finding at all, and stays in the log. Review gates are Gerrit-side: one committer's Code-Review+1, or two if the author is not a committer; an OWNERS approval per file; Owners-Override+1 for gardeners and Release Program Managers; Bot-Commit+1 from the Rubber Stamper on clean reverts and cherry-picks, which never grants OWNERS approval, by design (docs/code_reviews.md:27–29, 235–313).

Which tryjobs run

commit-queue.cfg is 9,451 generated lines holding two config groups. cq watches refs/heads/.+ of chromium/src, with committers drawn from project-chromium-submit-access, dry-runners from project-chromium-tryjob-access, a tree_status verifier pointed at chromium-status, and one tryjob verifier listing 603 builders. fallback-cq carries fallback: YES, watches every refs/branch-heads/.* except the seven live milestone refs (7559, 7871, 7922, 7977, 8010, 8037, 8059) and runs a single builder, requires-testing-checker — 604 builders {} entries in the file (commit-queue.cfg:15–31, 9411–9450). Figure {{fig-cq-funnel}} is the funnel those 604 entries form.

The tree reports the blocking count three ways. Every required or path-based CQ builder also gets a cq input property for BigQuery analysis; counting it in cr-buildbucket.cfg gives 37 required and 92 path-based, because the property is attached before includable_only and experiment_percentage apply. The blocking set is the one in infra/config/generated/cq-usage/default.cfg: 32 builders {} entries, matching cq-builders.md exactly. Use that file, not the property. And 126 of the 137 entries that are not includable_only carry the same default exclusions, infra/config/.+ and docs/.+, plus an include for their own generated directory — so a docs-only CL triggers nearly nothing, while editing one builder's properties runs that builder. The eleven that carry no path filter at all run on every CL: the two presubmit builders, the seven config verifiers, linux-full-remote-rel and requires-testing-checker.

Why CQ+1 then CQ+2 feels free

It is free, usually. Each tryjob gets a ReuseKey: a sha256 over the CL id, its MinEquivalentPatchset, and the values of any disable-reuse footers (luci-go cv/internal/tryjob/execute/reuse_common.go:192–220) from the tree. MinEquivalentPatchset survives Gerrit revision kinds NO_CHANGE, NO_CODE_CHANGE, MERGE_FIRST_PARENT_UPDATE, TRIVIAL_REBASE and TRIVIAL_REBASE_WITH_MESSAGE_UPDATE; only a REWORK forks it (luci-go cv/internal/gerrit/equi.go:24–76). Same key, same builder, build younger than staleTryjobAge = 24h, and CV adopts the existing build. Since 2026-07-27 CV can measure staleness in commits instead of hours, comparing the build's output Cr-Commit-Position against the branch tip; Chromium turned it on for one builder on 2026-09-18: linux_chromium_compile_dbg_ng, at reuse_max_commit_distance = 800 if settings.is_main else None (tryserver.chromium.linux.star:888–891). A worked example, measured on a live CL: 8423730's dry run was reused 14.4 hours later by its full run for 32 of 34 tryjobs. The two fresh launches were the presubmit builders — the only kind that always pays.
