{{S}}Every file wants something different

There is no best compressor, only a best match between what a file is and how it will be read (What Compression Keeps explains why). Three questions find the match.

First: is the file media, or already compressed? Four general-purpose codecs saved under 0.07% on a JPEG, a PNG, two MP4s, an Opus file, a .zip and a .tar.gz, and at most 4.66% on any media file. measured here What matters is the media codec and its quality (Already compressed). reconstruction

Second: is it small, and stored alone? Then framing can outweigh the saving. reconstruction gzip -6 made 1,216 of 1,409 synthetic messages under 200 bytes bigger, and gzip -9 grew 5 of 80 XO config files, all of 109 bytes or less. measured here

Third: how will it be read? A file compressed once and read often can afford a slow encoder and wants a fast decoder. reconstruction On synthetic API records, brotli 11 was densest (11.84×) but compressed at under 1 MB/s; zstd 3 decompressed at 500 MB/s or more. measured here Data read by offset is cut into frames, whose size sets the ratio: zstd 3 gives 2.08× in 1 KiB blocks of a real 6 MB JSONL audit log from a doomfly simulation run on this machine, and 8.68× in 1 MiB blocks. measured here Data read by column wants a columnar format first (Figure {{fig-decision}}). reconstruction

The answer, up front

Each row is my judgement, tested in the linked section. reconstruction Figure {{fig-headline}} has the measured headlines.

  • JSON over HTTP: brotli or zstd at the CDN, gzip as the fallback.
  • JSON at rest: zstd 3 to 9; a trained dictionary for many small documents, batches for streams.
  • Binary encodings: for a schema and typed values, not for size.
  • Config files (TOML, YAML, small JSON; see What the Parser Hears): never compress one by one.
  • Lockfiles and packages: the registry's format; for Cargo and npm, gzip level 9 tarballs. from the docs
  • JSONL logs: zstd in large blocks; seekable frames for random access.
  • Tables: Parquet (dictionary, RLE, zstd), not gzipped CSV.
  • Images: AVIF or JPEG XL for photos; lossless WebP or JPEG XL for graphics, oxipng if it must stay PNG.
  • Audio: Opus to listen, FLAC to keep.
  • Video: SVT-AV1 at preset 4 to 6 to store; H.264 to play anywhere; HEVC where hardware demands it.
  • Already compressed: store it; never gzip it.
